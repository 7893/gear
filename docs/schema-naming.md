# Schema 命名与统一配置

业务 namespace 为 `gear_2026`，内部函数 namespace 为 `gear_private_2026`。后缀表示创建年份，今后不按年更换；内部 namespace 不加入 Data API 暴露列表。

## 一份应用配置

`GEAR_DB_SCHEMA` 是应用侧唯一配置入口。本地记录在已忽略的 `.env`，发布使用同名仓库 Secret，独立 Edge 函数使用同名项目运行配置；各环境从同一私有记录同步值，互不自动继承环境变量。

- 发布脚本将值写入网站 `runtime-config.json` 的 `databaseSchema`；SDK 使用该字段初始化，缺失或格式不合法时拒绝启动。
- 网关将该值用于 Supabase 请求的 Profile；为已缓存旧页面接受去掉年份后缀的旧业务名，但上游始终使用当前配置，其他 schema 仍被拒绝。
- 密码找回、审核通知及待部署的附件服务从各自运行环境读取同名配置，不写死 Profile。

Schema 名称本身不是秘密；真实连接地址、账号、密钥和部署标识仍只保存在私有配置，不能写入公开文档或代码。

## 数据库对象与迁移

环境变量决定应用访问哪个 namespace，不会重命名数据库中已经存在的对象。历史迁移 001–006 保留原样，新增迁移 007 完成实际改名；字符串函数体的限定引用和调度命令随迁移同步。

已执行的 SQL 不能因为改了配置就被重写，否则新安装与旧安装会出现不同的历史。迁移中的确定目标名属于数据库变更记录；应用日常调用统一走配置。

## 本次范围与状态

迁移 007 已获授权执行，云端核对设备、单据、编号序列、对象身份及权限保持不变；独立邮件函数已同步为读取配置。网站和网关按本提交的 CI/CD 发布，提交、运行和配置的对应结果仅保存在私有发布记录。执行顺序是保留临时兼容入口、追加新 API 暴露项、同步独立函数与发布配置、通过 CI/CD 切换网站和网关，最后移除旧 API 暴露项及兼容入口。保留其他应用的暴露项、结构、用户、文件和设置。

改名不办理领用、退回或发信，不改变设备、单据、账号及编号。改名当时附件迁移顺延为 008，未执行云端；该次改名不创建桶、不部署附件函数，也不启用签字件功能。后续附件迁移、桶与函数已按单独授权部署，当前状态见[签字件实施](evidence-implementation.md)。
