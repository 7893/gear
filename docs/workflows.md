# 业务流程草案

以下为业务流程说明，状态、权限和更正口径以[统一业务规则](business-rules.md)为准。

## 0. 存量设备首次建账（建议）

已确认总量为几十件、预计不到一百件，部分在经办人手里，部分由个人或团队持有。建议通过“登记已有设备”直接录入当前持有方和设备状况；团队登记负责人，旧编号原样保留。

系统记录建账事件，不虚构历史领入或分发。已知的历史日期与凭证可补录，未知日期留空，无凭证明确标注。后续发生的真实交接统一进入下列正式流程。字段细节见[页面与表单](screens-and-forms.md)。

## 1. 批量领入

1. 登记来源单位或交付方、日期和设备清单。
2. 为设备建立台账，关联同一领入批次。
3. 核对每件设备实际正常或故障，确认领入后记为在管库存，生成领入单编号。
4. 打印领入单，双方签字。
5. 上传签字件，识别匹配单据，经办人核对后归档。

若交付方已有纸质单据，允许上传对方单据，另存外部单号并关联内部记录，避免重复签字。此流程已确认。

## 2. 分发使用

1. 选择一台或多台可分配设备。
2. 选择组织、团体或个人；团体必须登记接收负责人，具体使用人可后补。
3. 临时使用填写预计归还日期；长期使用可不填。
4. 确认实际交接，更新设备当前持有人，生成分发单。
5. 打印签字，上传并核对归档。

## 3. 动态分配

- 借调、挂职、临时人员均可登记为接收对象，无需成为系统用户。
- 延期：调整预计归还日期，保留原期限和变更记录。
- 直接转交：原持有人交给新持有人，生成转交单并更新去向。
- 收回再发：先办理退回，再按普通分发流程交给下一人。
- 到期仅标记待跟进或逾期，不自动视为归还，也不自动释放设备。
- 到期通过系统内提示和邮件提醒；收件人及发送时机在详细设计时确定。

## 4. 正常或故障退回

1. 选择当前持有人名下实际退回的设备，允许只退原单中的一部分。
2. 记录退回原因、设备状况、接收方与日期。
3. 正常退回经办人后，可再次分配。
4. 故障退回经办人后，标记故障，不允许直接分发。
5. 经办人退给原发放单位或供应方时，记录退往对象和新的交接单。
6. 每次退回均可打印、上传签字件并归档。

已确认支持使用人退回经办人，也支持直接退往上游；按实际交接记录接收方，不要求虚构一次经办人入库。同一实物维修后再领回沿用内部编号，重新核对状况；换成另一件实物则新建台账。

## 5. 签字件回传

1. 从单据详情上传图片或 PDF；也可提供统一上传入口。
2. 优先通过单据二维码或编号匹配，显示候选单据及附件供核对。
3. 识别失败或匹配不唯一时，由经办人手动选择，不能自动关联错误记录。
4. 核对后标记凭证已归档，保留原始文件。
5. 多页单据允许上传多张图片或一个多页 PDF。

建议每页打印单号与页码，二维码不直接包含人员等敏感明细。

## 6. 查询

- 从设备查看当前持有人、位置、状况及完整流转记录和关联单据。
- 从人员或团体查看当前持有清单及历史归还记录。
- 从单据编号找到整批设备、交接双方和签字附件。
- 查看在库可用、使用中、故障、待归还及待回传签字单等清单。
