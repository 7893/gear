# 第一阶段账号接入

状态：账号事务迁移已应用，Vue 页面、Gmail 认证邮件适配代码及隔离验证已完成。真实管理员尚未指定；共享 Auth 回调、Data API 暴露和发信 Hook 尚未更改。线上账号开关保持关闭，不能把本阶段代码验证视为真实注册发信验收。

## 数据库接口

[迁移 002](../database/migrations/202610170002_accounts.sql) 仅新增设备簿自己的函数，不改变共享认证表或配置。

| `gear` RPC | 权限及用途 |
| --- | --- |
| `get_my_membership()` | 已登录身份仅查询自身当前邮箱验证和成员状态 |
| `apply_for_access(display_name)` | 已验证邮箱明确申请；只建立待审核成员，重试不重复申请，不自动恢复拒绝或停用 |
| `list_members(filter_status)` | 当前有效管理员读取审核名单与必要邮箱资料 |
| `set_member_access(target_member_id, expected_version, new_status, new_role, reason, request_id)` | 管理员审核、角色调整、停用和恢复；版本冲突及同幂等键不同参数拒绝 |

公开入口使用 `SECURITY INVOKER`，固定调用未暴露 schema 中的内部实现。内部函数检查真实 `auth.uid()`、数据库当前角色及邮箱验证，固定空 `search_path`，不接收或信任表单指定的经办人身份。`anon`、普通服务角色没有这些函数的默认执行权；客户端仍不能直接写业务表。

申请与管理变更先锁定设置单行，在等待后重新验证管理员权限；并发停用或降级后至少保留一个当前邮箱已验证的有效管理员。已有其他应用的 Auth 身份只能查询自身状态并明确申请，不自动授予角色。审核生成审计及必要待发记录，邮件发送开关继续关闭，没有在事务中发信。

## 首次管理员

[bootstrap_admin.sql](../database/bootstrap_admin.sql) 是可公开复用的一次初始化入口，由部署者作为数据库拥有者手动执行：

1. 指定用户自行完成注册、验证邮箱和设置密码；已有共享身份使用原密码登录，不由部署者覆盖。
2. 在私有环境设置 `GEAR_ADMIN_EMAIL`、`GEAR_ADMIN_DISPLAY_NAME`；使用已配置且经过核对的数据库连接环境运行 `psql -X --file database/bootstrap_admin.sql`。
3. 脚本只匹配该邮箱，调用仅拥有者可执行的内部函数；要求身份存在且邮箱已验证。已有管理员时不能再初始化其他人；同一个已初始化管理员重复执行不改姓名、密码或审计。

邮箱对应多个认证身份时安全失败，不随意挑选。没有默认管理员、公开初始化按钮、预设密码或首个注册者提权。此脚本不用于无条件恢复丢失的管理员，恢复须另行核对和授权。

## 前端与验证

[web](../web/README.md) 使用 Vue 3 + Vite + Vue Router，保留轻量本地样式和原连接检测。新增注册、验证、登录、状态及管理员成员操作页；新注册者验证后提交此前明确的申请，已有共享身份首次进入时填写姓名并明确申请，hash 路由复用既有源站。`accountsEnabled` 默认关闭，只有共享配置和实际验收完成后再开启。

已在隔离 PostgreSQL 17 验证：新迁移及重跑保护、并发申请去重、审核幂等、拒绝与停用不能自行恢复、非管理员越权拒绝、邮箱失去验证后不能启用、最后管理员并发保护，以及拥有者初始化的权限和幂等。CI 同时使用独立 PostgreSQL 16 临时集群。

Playwright 使用虚构 Auth/RPC 响应验证六项页面流程；它验证页面行为，不代表已与真实 Supabase Auth 完成集成。邮件适配器只使用模拟 Google 响应，未发送真实邮件。大陆访问、真实验证邮件、首次管理员登录与实际审核仍待配置后验收。

## 已核对、尚待批准的共享配置

现有项目允许邮箱注册且要求验证，尚无自定义 SMTP 或发信 Hook，验证回调白名单为空，`gear` 尚未暴露。认证邮件限额保持现有每小时 2 封，密码最短 6 字符、JWT 一小时等全项目参数均未改变。默认 SMTP 仅向项目团队邮箱发送，不足以用于公开注册。[官方说明](https://supabase.com/docs/guides/auth/auth-smtp)。

待执行的具体变更：

3. 部署独立 `gear-auth-mail`，仅该函数关闭 JWT 校验，改由 Hook 签名校验；通过 `GEAR_` 前缀注入所需六项机密，保留其他函数和机密。

5. 注册邮件限额是否调整由用户批准具体值；建议每小时 20 封，保留验证请求和单地址重发间隔等其他原有参数。此处为待批准建议，尚未执行。
6. 指定首个管理员。共享配置检查通过后将 `GEAR_ACCOUNTS_ENABLED=true` 开放账号入口，由本人完成注册及邮箱验证；此时仍只得到待审核成员。部署者核对指定身份后执行初始化脚本，再验收管理员登录及真实审核流程。若指定身份已经存在且邮箱已验证，也可先初始化再开放入口；两种路径均不会把首个注册者自动设为管理员。

真实地址、发件身份、资源标识、回调差异和机密原文只保存在私有部署记录中。网站 CD 继续只发布前端和网关，不自动执行 SQL、发布邮件函数、设置 Hook 或初始化管理员。上述共享变更尚未获得本次具体操作授权，不会因为网站发布而自动启用。
