## 数据库接口

[迁移 002](../database/migrations/202610170002_accounts.sql) 仅新增设备簿自己的函数，不改变共享认证表或配置。

| `gear` RPC | 权限及用途 |
| --- | --- |
| `get_my_membership()` | 已登录身份仅查询自身当前邮箱验证和成员状态 |
| `apply_for_access(display_name)` | 已验证邮箱明确申请；只建立待审核成员，重试不重复申请，不自动恢复拒绝或停用 |
| `list_members(filter_status)` | 当前有效管理员读取审核名单与必要邮箱资料 |
| `set_member_access(target_member_id, expected_version, new_status, new_role, reason, request_id)` | 管理员审核、角色调整、停用和恢复；版本冲突及同幂等键不同参数拒绝 |

公开入口使用 `SECURITY INVOKER`，固定调用未暴露 schema 中的内部实现。内部函数检查真实 `auth.uid()`、数据库当前角色及邮箱验证，固定空 `search_path`，不接收或信任表单指定的经办人身份。`anon`、普通服务角色没有这些函数的默认执行权；客户端仍不能直接写业务表。

申请与管理变更先锁定设置单行，在等待后重新验证管理员权限；并发停用或降级后至少保留一个当前邮箱已验证的有效管理员。已有其他应用的 Auth 身份只能查询自身状态并明确申请，不自动授予角色。审核生成审计及必要待发记录，邮件发送开关继续关闭，没有在事务中发信。

## 首次管理员

[bootstrap_admin.sql](../database/bootstrap_admin.sql) 是可公开复用的一次初始化入口，由部署者作为数据库拥有者手动执行：

1. 指定用户自行完成注册、验证邮箱和设置密码；已有共享身份使用原密码登录，不由部署者覆盖。
2. 在私有环境设置 `GEAR_ADMIN_EMAIL`、`GEAR_ADMIN_DISPLAY_NAME`；使用已配置且经过核对的数据库连接环境运行 `psql -X --file database/bootstrap_admin.sql`。
3. 脚本只匹配该邮箱，调用仅拥有者可执行的内部函数；要求身份存在且邮箱已验证。已有管理员时不能再初始化其他人；同一个已初始化管理员重复执行不改姓名、密码或审计。

邮箱对应多个认证身份时安全失败，不随意挑选。没有默认管理员、公开初始化按钮、预设密码或首个注册者提权。此脚本不用于无条件恢复丢失的管理员，恢复须另行核对和授权。
