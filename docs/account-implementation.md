## 数据库接口

[迁移 002](../database/migrations/202610170002_accounts.sql) 仅新增设备簿自己的函数，不改变共享认证表或配置。

| `gear` RPC | 权限及用途 |
| --- | --- |
| `get_my_membership()` | 已登录身份仅查询自身当前邮箱验证和成员状态 |
| `apply_for_access(display_name)` | 已验证邮箱明确申请；只建立待审核成员，重试不重复申请，不自动恢复拒绝或停用 |
| `list_members(filter_status)` | 当前有效管理员读取审核名单与必要邮箱资料 |
| `set_member_access(target_member_id, expected_version, new_status, new_role, reason, request_id)` | 管理员审核、角色调整、停用和恢复；版本冲突及同幂等键不同参数拒绝 |

公开入口使用 `SECURITY INVOKER`，固定调用未暴露 schema 中的内部实现。内部函数检查真实 `auth.uid()`、数据库当前角色及邮箱验证，固定空 `search_path`，不接收或信任表单指定的经办人身份。`anon`、普通服务角色没有这些函数的默认执行权；客户端仍不能直接写业务表。

申请与管理变更先锁定设置单行，在等待后重新验证管理员权限；并发停用或降级后至少保留一个当前邮箱已验证的有效管理员。已有其他应用的 Auth 身份只能查询自身状态并明确申请，不自动授予角色。审核生成审计及必要待发记录，邮件发送开关继续关闭，没有在事务中发信。

## 首次管理员

[bootstrap_admin.sql](../database/bootstrap_admin.sql) 是可公开复用的一次初始化入口，由部署者作为数据库拥有者手动执行：

1. 指定用户自行完成注册、验证邮箱和设置密码；已有共享身份使用原密码登录，不由部署者覆盖。
2. 在私有环境设置 `GEAR_ADMIN_EMAIL`、`GEAR_ADMIN_DISPLAY_NAME`；使用已配置且经过核对的数据库连接环境运行 `psql -X --file database/bootstrap_admin.sql`。
3. 脚本只匹配该邮箱，调用仅拥有者可执行的内部函数；要求身份存在且邮箱已验证。已有管理员时不能再初始化其他人；同一个已初始化管理员重复执行不改姓名、密码或审计。

邮箱对应多个认证身份时安全失败，不随意挑选。没有默认管理员、公开初始化按钮、预设密码或首个注册者提权。此脚本不用于无条件恢复丢失的管理员，恢复须另行核对和授权。

## 已授权并应用的共享配置

现有项目继续允许邮箱注册并要求验证，不启用邮箱自动确认；共享密码最短 6 字符、JWT 一小时等其他参数保持不变。未配置自定义 SMTP，认证邮件现由 Send Email Hook 提交 Gmail，替代原有默认发信路径。[官方说明](https://supabase.com/docs/guides/auth/auth-hooks/send-email-hook)。

1. Data API 原有 schema 列表追加 `gear`，保留全部原项，`gear_private` 不暴露。
2. Auth 验证回调列表追加设备簿 HTTPS 根入口，保留原有 Site URL 及其他回调。
3. 独立部署 `gear-auth-mail`，仅该函数关闭平台 JWT 校验，改由 Standard Webhooks 签名及时间戳校验；六项运行机密使用 `GEAR_` 前缀。
4. 全项目 Send Email Hook 指向该函数。所有应用的认证邮件使用既有 Gmail 发件身份及通用模板；该共享影响已获授权。原有七类安全通知开关均保持关闭，没有擅自开启。回滚时恢复私有快照中的原 Hook 配置、回调、限额和 API 列表；关闭账号发布开关后重新发布。
5. 认证邮件限额改为每小时 20 封，保留验证请求和单地址重发间隔等其他参数。Google 接受提交不等于收件人已收到。
6. 已开启仓库变量 `GEAR_ACCOUNTS_ENABLED`，通过既有网站 CI/CD 发布。指定管理员本人先注册、验证，此时仍只得到待审核成员；部署者核对指定身份后执行初始化，再验收管理员登录及审核。尚未指定邮箱，未初始化任何真实管理员。

应用前后对比通过：其他 Auth、REST 参数及数据库结构未改变，原有函数代码摘要与 JWT 配置、原有机密值摘要保持一致。Supabase 在新增项目级机密后自动提升了现有函数版本号并刷新机密更新时间；这属于平台重新部署元数据变化，不能称为现有函数元数据完全未变。

真实地址、发件身份、资源标识、回调、完整配置快照及机密原文只保存在忽略的项目环境或私有部署记录中。网站 CD 继续只发布前端和网关，不自动执行 SQL、发布邮件函数、设置 Hook 或初始化管理员。共享邮件 Hook 的真实收发和首个管理员尚未完成验收，不能以配置成功替代这些检查。

## 六位验证码调整

按最新要求，设备簿注册改为仅输入六位 ASCII 数字验证码，不发送注册验证链接。注册成功提示后自动进入验证页并保留邮箱，不把邮箱放入地址栏或路由参数；前端表单及提交函数均验证恰好六位数字，保留开头的零。邮件模板通过已有 `gear_application_name` 注册标记选择设备簿模板，该标记不参与权限授予；其他应用继续使用现有通用邮件及链接。

本地代码检查、七项浏览器流程及七项邮件用例已通过，包括错误长度、非数字、全角数字、前导零以及设备簿邮件不含链接或哈希。该调整尚未发布：共享 Auth 当前 `mailer_otp_length=8`，必须单独获准改为 `6` 后再发布严格六位的页面与邮件函数，避免服务器生成八位而客户端只接受六位。有效期、发送限额及其他配置不因此变更。真实收发仍待验收。
