## 已修复的问题

1. **Storage 缺键兼容**：备份工具统一识别 HTTP 400/404 中明确的 `NoSuchKey` 或旧版语义 404 缺键响应。缺桶、权限不足、不明响应和上传失败均中止；不把任意错误当成空位，不覆盖原件。
2. **旧版恢复兼容**：恢复后邮件隔离按实际存在的字段执行，支持迁移 013 及 021。已有邮件开关关闭、未发送任务取消并清除租约、恢复记录追加仍在同一数据库事务；不修改共享 Auth，不自动重发历史邮件。
3. **单位设置版本同步**：抬头与到期提醒共同读取一致版本，保存互斥，成功后统一刷新。保存一项保留另一项尚未提交的字段和原因；响应丢失重试使用原请求标识。读取版本不一致会重读，仍冲突或刷新失败时禁止继续使用旧版本提交。手动“刷新设置”会重新读取并重置表单。
4. **通知发布入口**：本地 Supabase 配置补齐独立通知函数的入口和 import map，保持认证 Hook 与附件服务各自的入口和校验模式。后端迁移、函数、网站及可选提醒启用的顺序见[发布流程](deployment.md#待上线业务的发布顺序)。这是准备好的配置，未执行部署。

## 公共能力的落点

| 公共模块 | 统一负责 | 使用入口 |
| --- | --- | --- |
| [useAuthorizedAction](../web/src/useAuthorizedAction.ts) | 提交状态、安全错误、同内容重试标识、失权或离开时丢弃回调、可取消传输及表单重置 | 设置、延期、使用人补录、接收对象创建、人员维护、资料更正、故障维修、设备处置、单据处理、导入、附件与下载 |

| [useUnitSettings](../web/src/useUnitSettings.ts) | 一份设置快照、共享版本、互斥保存、通知及刷新 | 单位抬头、到期提醒两个纯字段表单 |
