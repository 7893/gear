# 领入、分发、退回与打印单据

状态：迁移 006 已获授权应用云端，页面通过既有主分支 CI/CD 发布，独立开关开启。隔离检查及云端权限、数据保留核对通过；随后按授权完成演示业务接口与正式快照 PDF 验收；已登录表单操作及实际打印机仍待验收。统一进度见[实现状态](implementation-status.md)。

## 本轮范围

- 领入：来源单位或交付方直接填写；同型号按数量展开为逐件明细，各自补充旧编号、序列号、位置和实际正常或故障。新设备在确认时才建账；已退上游的原设备领回沿用内部编号。
- 分发：选择在库可用设备，给同一个个人或团队；个人负责人为本人，团队选择有效个人。每单一个长期或临时使用期限，临时期限不得早于交接日期。
- 退回：从同一个持有方和交出负责人名下选设备，支持部分退回；逐件核对正常或故障，故障须说明，整单填写退回原因。可退经办人库存，也可实际直接退往上游；库存也可退上游。原持有方或负责人停用不阻止实际退回。
- 单据：草稿保存、编辑、删除、核对确认、列表查询和详情；正式单据提供同一 A4 打印骨架与另存 PDF。

故障处置已按授权接入；正式单据作废及追加更正说明已[本地实现](document-review-implementation.md)、待授权上线。导出、到期邮件与单位抬头设置入口仍在后续阶段。签字件上传和识别归档已[按授权部署](evidence-implementation.md)，迁移 008 及私有文件服务已上线，真实签字件归档待本人验收。逐设备延期和站内到期查询已[按授权接入](temporary-use-implementation.md)，迁移 009 已应用，页面随本轮发布。转交与团队负责人交接已在同一表单和事务中[按授权接入](transfers-implementation.md)，迁移 010 已应用，页面随本轮发布；真实交接待本人验收。迁移 006 阶段仅兼容显示已有作废状态；新增处理入口的范围与验证见单据处理实施。

## 数据库与接口

[迁移 006](../database/migrations/202610190006_flows.sql) 仅改变设备簿：为 `gear_2026.documents` 增加 `remarks`，为 `gear_2026.document_items` 增加 `allow_legacy_duplicate`，再增加五组公开接口与内部实现、两个私有辅助函数。没有新业务表、共享 Auth、Storage、邮件、扩展或调度配置。

| 接口 | 用途 |
| --- | --- |
| `gear_2026.list_documents(search, kind, state)` | 按单号、双方或实际交接人文字搜索及类型、状态筛选 |
| `gear_2026.get_document(document_id)` | 读取单据及逐件明细；正式记录包含确认时快照 |
| `gear_2026.save_document(details, items, request_id, document_id, expected_version)` | 新建或更新有权访问的草稿，不改变实物去向 |
| `gear_2026.delete_document(document_id, expected_version, request_id)` | 删除草稿和明细，保留无强外键的删除审计 |
| `gear_2026.confirm_document(document_id, expected_version, request_id)` | 原子确认整单并生成永久单号及事件 |

管理员可处理全部草稿，经办人只能处理自己的草稿；查询人只读正式单据。三种角色均须邮箱已验证、成员已启用。匿名、停用和未审核身份无权读取业务；`service_role` 不增加执行权。私有记录及日期辅助函数不授予客户端执行权，不增加直接写表、取设备号或单据流水权限。

写入先取既有设置单行锁，再核对当前真实身份，之后锁定草稿及按稳定顺序锁定设备。输入字段采用固定白名单、类型及长度校验；单据最多一百件，同一实物不能重复选择。现有设备带选择时版本，草稿带读取时版本；确认再检查当前状态、分配和责任人。任一失败整单回滚，草稿和填写内容保留；错误会指出已识别的冲突内部编号或重复旧编号的行号，其他诊断不展示。

保存、删除和确认各以事件中的唯一请求标识去重，同一当前账号和相同请求返回最初结果，换内容或账号则报冲突。权限检查在返回旧结果之前；删除草稿不删除审计，正式确认后不能改写单据业务字段和明细。客户端保留当前表单内的请求标识，响应丢失时可原样重试；刷新或重登后先查单据，不宣称跨刷新永久去重。

确认一次完成单据、明细、设备、使用分配和不可改写事件。每件设备各有变化事件，另有整单确认事件；新领入不附加虚构建账或旧交接事件。部分退回只关闭所选分配；退上游退出在管，修好再领回恢复库存，不自动恢复旧使用期限。`confirmed_revision` 保存被确认的草稿版本，后续单据版本变化不改它。

## 编号与时间

已随本轮上线确认并按[统一参数](business-rules.md#10-待确认的实施参数建议)实现：领入 `LR-YYYYMMDD-0001`、分发 `FF-YYYYMMDD-0001`、退回 `TH-YYYYMMDD-0001`，类型共用同一业务日流水，至少四位、超过后扩展。编号规则已确认；上线核对未办理交接，随后授权演示验收已分别生成三类正式单号。

编号日期取确认时刻在东八区的当天，补录的实际交接日期不决定编号；草稿不取号，重试及重打不换号。设备仍使用已确认的 `SB-000001` 格式，不回拨或复用序列。允许失败事务或维护造成空号。

实际交接日期是必填纯日期，不晚于业务当天，不早于既有设备最近有效流转及已知使用起始日期；同日按事件顺序。未知历史起始日期不自动补成今天。时间点以 UTC 输出和保存，页面按东八区显示。

## 页面与打印

| 路由 | 内容 |
| --- | --- |
| `/#/flows` | 办理入口和草稿查询 |
| `/#/documents` | 单据列表与筛选 |
| `/#/documents/new?kind=receipt` | 领入；`issue` 为分发，`return` 为退回 |
| `/#/documents/:id/edit` | 编辑有权访问的草稿 |
| `/#/documents/:id` | 详情、删除草稿、打印或另存 PDF |

`GEAR_FLOWS_ENABLED` 只在字面 `true` 时开放，缺省关闭，且要求台账开关已开。前端权限或身份变化时清除旧业务数据，并丢弃迟到响应；后端授权仍为最终边界。保存失败保留输入，确认前列出双方、实际移交和接收人、数量、日期及期限；实际确认使用保存后的草稿。

正式打印只用确认时保存的设备、双方、负责人、期限、经办人及抬头快照，不再查询当前名册或设备资料拼接旧单。草稿可预览打印但显著标注，未编号、无正式二维码；已作废记录显著标注，不用作有效交接凭证。

A4 表格自然分页，表格续页重复表头、双方及二维码，各页标注单号和页码，长文本换行不省略；汇总与签字区保留，签字区不拆开。二维码在浏览器本地生成 SVG，只编码 `gear:document:` 加单据标识，不含人员、地址、令牌或登录能力。浏览器自带网址页眉页脚建议关闭。

桌面 Chromium 已生成并检查包含五十件设备、长旧编号及长备注的 PDF：各页单号、续页表头、所有设备、备注末尾和完整签字区均保留。其他浏览器、实际打印机和签字件回传尚待实际验收。[Chrome 页边距与页码说明](https://developer.chrome.com/blog/print-margins)、[二维码组件官方接口](https://github.com/kazuhikoarase/qrcode-generator/tree/master/js)及[随网站分发的许可](../web/public/qrcode-license.txt)。

## 授权演示验收

在现有云端环境中，以有效管理员身份通过现有业务 RPC 办理，未改表、权限、登录凭据或共享配置：

- 选择三台库存可用的演示设备，临时分发给已有演示团队及其个人负责人，期限十四天。
- 保存草稿时设备状态保持不变；确认后生成正式分发单及三条使用分配。
- 从同一单中正常退回一台，库存恢复；另外两台的团队、负责人和归还日期仍正确。
- 新领入一台明确标注演示的碎纸机，分配新的永久内部编号；当前设备总数五十一台。
- 三类单据均确认成功，原样重复确认返回同一结果，没有重复设备、单据或使用分配；退回后原分发单仍与确认时快照完全一致。
- 既有账号、接收对象、其他设备和其他应用保持不变；没有生成邮件任务或发送测试邮件。

三张实际单据均由项目现有打印组件加载确认快照，在本地 Chromium 生成 A4 PDF；核对正式单号、设备明细、负责人、期限、二维码和签字栏，并检查三张 PDF 的实际布局。实测发现页面根元素底色会落在纸张空白区域，已统一打印画布为白色；三张实际单据重新生成并核对背景，既有五十行多页 PDF 回归及构建通过。打印渲染未使用真实登录会话，不等于已经验收已登录页面的全部表单交互或实体打印机。签字栏为空，未模拟签名或归档。

完整输入、请求标识、前后快照、PDF 和新增设备、单据、明细、事件及分配标识仅保存在私有验收清单；原始演示批次清单已关联这些后续记录。正式切换前清理须包含上述依赖，保留真实数据和已使用编号。

回退入口时关闭流转开关并重新发布；保留迁移、单据、编号及历史，不通过删除列或业务记录回退。原始配置、只读核对、实际身份和资源标识仅保存在已忽略的私有记录中。
