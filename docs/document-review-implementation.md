# 正式单据作废与更正说明

状态：已完成本地实现，全部六十三项浏览器检查、格式、类型检查及构建通过；隔离数据库检查和相关业务回归通过。迁移 012、推送及生产发布待单独授权。页面复用单据详情和公共组件；本轮不办理生产单据，统一进度见[实现状态](implementation-status.md)。

## 管理员入口

仅当前邮箱已验证、启用的管理员可以处理已确认单据。经办人和查询人可以读取处理记录，没有写入口；后端再次核对身份，不能凭前端显隐或旧会话取得权限。草稿继续使用原编辑和删除入口，已作废单不可恢复或再次处理。

单据详情提供两个操作，共用 [DocumentReview.vue](../web/src/components/DocumentReview.vue) 和公共按钮组、中文错误、请求标识及授权查询，不按领入、分发、转交和退回分别实现处理页面。处理原因必填，最多两千字。提交失败保留填写内容；相同内容重试复用请求标识，身份变化或离开后的迟到响应不会恢复旧表单。

## 整单作废

仅处理实际交接不成立的误录。管理员填写原因，明确勾选已核对误录后确认；不能用作废代替真实退回或后续交接。

服务端按同一事务逐件核对。原确认事件必须是该设备最新、未被抵消的有效状态事件；后续流转、故障、维修、延期、负责人交接或退出记录均会阻止直接作废。即使当前状况碰巧变回相同值，存在后续事件仍然拒绝。已被作废的状态事件及抵消事件本身不再当成有效后续依赖，因此允许从最新误录单起逐张核对作废，不提供自动级联撤销。

当前管理状态、状况、位置、最近实际交接日期及持有关系、负责人、起始日和期限也必须与原单结果一致；冲突时整单失败，不能只恢复其中几台。仅恢复交接相关字段，名称、型号等后来资料更正继续保留，重叠字段有冲突则停止。

分发产生的分配被关闭；退回或普通转交关闭的原分配重新打开，保持原分配 ID、原起始日、期限、来源和跟进人。团队负责人交接在同一分配内恢复原负责人。未知历史起始日继续为空，设备版本只增不减。实际已退上游的原设备沿用同一编号恢复到原管理状态。

若误单首次创建了设备，将该台账标记无效，永久保留设备及编号；不删除设备、使用记录、单据、事件或原件。每件设备追加抵消事件，使用已有唯一 `reverses_event_id` 指向原确认事件，并在设备历史关联原单。

原单变为已作废，原正式编号不变、不退号、不复用，冻结明细及双方快照不变；重打显示已作废。原附件及归档信息保留供查阅，不能继续当成有效交接凭证。需要正确新单时重新办理，不重启原单。

## 追加更正说明

用于记录原单有误的内容及正确事实，要求填写独立更正原因和最多四千字的更正说明。原单仍为已确认；更正不会改写原正式字段、打印快照、设备现状、数量或期限。每次保留原单快照、说明、时间和管理员，详情显示全部记录；处理记录作为补充内容随页面打印，原单正文仍保留。

这不是修改原签字件或自动取得签字方认可的入口。实际去向或期限变化继续使用对应业务；需新签字单时重新办理。当前不提供直接重写正式单据字段或绕过历史顺序的管理员接口。

可选择关联后续确认的同类型替代单。后端要求编号顺序晚于原单，拒绝自身、草稿、作废单、其他类型及较早单据，避免循环引用。替代单被仍有效的原单更正记录引用时，不能直接作废；需先核对真实业务，不能留下看似有效但已撤销的替代凭证。

更正仅追加记录和推进单据版本，不改归档原件及其核对状态；更正说明本身不自动成为新签字凭证。再次上传或更换已归档附件仍使用原有管理员更正与人工核对流程。

## 数据库与事务

[迁移 012](../database/migrations/202610190012_document_review.sql)不增加表、列或触发器。新增 `void_document(document_id, expected_version, reason, request_id)` 和 `correct_document(document_id, expected_version, reason, correction_text, replacement_document_id, request_id)` 两组公开与私有函数，以及一个只供内部调用的管理员资格函数。

扩展既有私有 `document_record`，通过原查询接口提供处理记录；保留原函数对象身份和授权。事件类型约束只增加 `document_corrected`，保留全部旧值。迁移先核对旧读取函数体及事件约束指纹，未知变更或重跑时整体失败，不覆盖新版本配置。

写入顺序沿用设置单行锁、当前成员资格、请求去重、单据版本、设备及分配锁。作废与分发、延期、故障、附件及角色变化采用既有锁顺序；任何冲突整体回滚。两组公开接口只给认证角色执行权，实际仍要求有效管理员；匿名、服务角色没有新增执行权，内部资格函数不对用户开放。

幂等重试返回首次处理结果，换操作者或内容拒绝；权限核对在重试前进行。操作日期由服务端按东八区计算，记录时间存 UTC；恢复旧业务日期不篡改原事件时间或系统记录顺序。

## 验证及上线边界

[隔离数据库检查](../database/tests/check_document_review.py)覆盖整单回滚、全部交接类型、团队负责人、逐张抵消、未知起始日期、原分配身份、后续故障维修及延期拒绝、重叠字段冲突、资料更正保留、新设备标记无效、归档原件保留、替代单引用、并发重试、作废与分发竞争、即时权限与旧版本拒绝。只使用临时 PostgreSQL、虚构身份及文件完成声明，不上传真实文件或伪造签字。

浏览器新增五个虚构 API 场景，检查作废及响应丢失重试、打印水印、补充记录打印及替代单关联、冲突保留表单、非管理员只读及失权后的迟到响应。既有流转、故障、分页、账号和附件继续回归；本地检查不等于真实单据作废、更正或纸张签字验收。

本轮仅完成本地代码、检查和文档。上线须单独授权应用迁移 012，再推送触发既有 CI/CD；网站 CD 不执行 SQL。执行前后核对原有数据、权限、序列及共享服务配置，不自动创建更正或作废记录、不发邮件。真实资源标识和部署参数仅存忽略的私有记录。

若需回退界面，撤下写入口并重新发布；已经存在的单据处理、抵消事件、原件和编号继续保留，不能删除历史来回退。
