# 签字件、编号识别与人工归档

状态：迁移 007、独立 Edge 函数及页面已本地实现并隔离验证，尚未应用云端或发布；`GEAR_EVIDENCE_ENABLED` 缺省关闭。云端只读核对时仍有五十一台设备、三张正式单据且无附件，目标私有桶与新函数均未创建。完整状态见[实现状态](implementation-status.md)。

## 办理规则

在有效正式单据详情中选择原件，识别候选仅供核对；用户明确确认上传到当前单据，上传成功进入待核对。签字、对应单号、设备及交接内容、完整页数四项均由人核对后归档。没有自动签名验证或自动归档，不因附件状态改变设备去向、使用分配、单据编号或打印快照。

支持逐张追加 JPEG/PNG 照片或一个多页 PDF。领入还可选择交付方原单，填写外部单号；无需为上传另办一次交接。格式不支持、PDF 加密或损坏、页数或大小超限时明确提示，原件不静默转换、压缩或截断。

本地暂按此前建议实施以下上限，须随上线范围确认，属于本项目规则而非平台免费额度：单件 20 MiB、每单十个有效附件和 100 MiB、单 PDF 二十页、图片四千万像素。待完成上传也占用数量和预留容量；取消后不算成功附件或当前归档文件。历史原件继续保留，实际存储总量可能超过当前有效文件的合计。

## 识别与预览

识别在浏览器中按需加载：图片读取二维码，PDF 逐页提取内置文字中的单号并渲染二维码；支持多页出现多个单号的情况。仅解析 `gear:document:` 加单据标识和规定格式单号，文本不作为指令。候选由受权限控制的数据库接口查找，上传仍绑定用户明确选择的当前单据。

识别结果记为 `browser_hint`，不作为服务端文件核验或归档结论。未找到、未识别或出现其他单号时，保留成功上传的原件，可重新识别、手动更正关联；归档必须补充人工核对说明。普通无二维码照片及纯扫描页尚无文字 OCR，后续确有需要再用脱敏样本选择服务。识别失败不阻止人工处理，不接入新的付费识别产品。

预览只在浏览器渲染图片或 PDF 当前页，支持翻页，不执行 PDF 动作或渲染可点击链接；需要时下载原件。QR、PDF 组件及 worker 都随网站构建提供，不使用第三方 CDN；PDF 模块按需加载。[组件许可](../web/public/evidence-licenses.txt)随网站分发。

## 文件与权限边界

新增独立[签字件函数](../supabase/functions/gear-evidence/README.md)，所有原件上传和下载均经过该函数。平台用户 JWT 校验之外，函数向 Auth 核实来访者，以来访者 JWT 调用业务接口；数据库再次检查当前邮箱验证、设备簿审核状态及角色。客户端不能自报操作者身份。

上传按实际字节限制整个请求和单文件，检查文件签名、容器结构、扩展名、图片尺寸及 PDF 可解析性和页数，计算 SHA-256。此核验不宣称具备杀毒、签名鉴真或全部图片解码验证能力。先通过普通业务接口预留随机对象名，服务端只插入原件、不覆盖旧对象；核验成功才调用仅授予服务角色的确认接口。服务角色不获得设备簿业务表读写权限，也不能调用普通经办接口。

原件位于专属私有桶。单独的[存储隔离脚本](../database/configure_evidence_storage.sql)对该桶拒绝匿名或登录客户端直接读写，包括生成可转交的下载链接；下载使用每次校验身份的函数响应。限制策略只约束私有环境传入的目标桶，不改变其他桶的既有权限。服务端使用平台内置服务凭据访问随机对象路径，不接收客户端提供的桶名、地址或对象路径。

下载前读取当前业务权限和成功附件记录，按保存的大小及哈希核对取回的原件，返回前再核对权限；响应不缓存。当前有效成员三种角色均可读取成功的历史或现用原件；经办人只查询自己的未完成上传，管理员可查看全部。账号停用或未审核、匿名、其他应用的未准入身份均不能读取原件。

## 数据库与并发

[迁移 007](../database/migrations/202610190007_evidence.sql)不增加业务表：为附件增加版本、预留大小、上传清单、来源类型和外部单号五列，增加原件不可改写触发器，并在事件类型约束中保留旧值、扩展预留及取消类型。新增七组公开接口与私有实现、三个私有辅助函数及一个仅服务端调用的完成接口，共十八个函数；既有函数不被替换。

| 接口 | 用途 |
| --- | --- |
| `gear.list_evidence` | 正式单据的附件、当前凭证状态与可见办理历史 |
| `gear.get_attachment` | 校验当前成员及业务关系，读取成功原件或有权处理的预留记录 |
| `gear.match_evidence` | 从有限的编号线索查询正式单据候选 |
| `gear.reserve_attachment` | 核对单据版本、角色、重复文件及数量/容量后预留对象 |
| `gear.cancel_attachment` | 取消有权处理的未完成上传，不删除原件或单据 |
| `gear.update_attachment` | 填写原因后调整关联、当前归档用途、外部单号或重试识别结果 |
| `gear.archive_evidence` | 按版本、完整现用附件清单及四项人工确认完成归档 |
| `gear.commit_attachment` | 仅服务端提交实际文件核验结果，普通客户端不能执行 |

所有写入先锁定既有设置单行，复核当前权限，再核对版本并修改关联。预留、取消、更正及归档采用请求标识和完整输入去重；服务端完成采用附件标识去重。权限检查先于旧结果重放。上传响应丢失时，在当前表单保留原文件和请求标识；已存在对象须核对内容一致，已完成记录直接读取，不覆盖文件或新增流转。刷新或重新登录后应先检查附件状态，不承诺跨刷新保存客户端重试状态。

已归档凭证新增文件或更正关联、用途，仅管理员填写原因后办理；原件不变，旧关联及核对状态写入不可改写审计，涉及的单据退回待回传或待核对。所有当前采用的成功原件须重新核对，不能遗漏待完成上传。退出当前归档用途仅设为历史保留，不删除文件。替换可先追加新原件，再注明原因将旧原件移出当前归档用途；本轮不自动设置 `supersedes_id`。

服务端确认在安全定义者内部完成设备簿延迟约束检查，无需为服务角色扩大表权限。未上传完成、识别失败、权限丢失、版本冲突分别处理；不会重新确认设备交接或生成邮件。

## 已执行的本地验证

- 数据库临时集群：并发预留去重、仅服务端核实文件、成功确认去重、四项核对、管理员更正、旧关联审计、识别失败保留、全部有效原件重审、取消及容量、即时失权和原件不可删除或覆盖。
- 模拟 Storage：即使存在无关的宽泛许可，本桶仍拒绝客户端直接访问，其他桶读取不受影响。
- 独立函数检查：实际 PDF 文件和哈希、权限拒绝、不可覆盖、上传响应丢失、下载复核、加密/损坏 PDF、页数及请求大小、PNG 容器和尺寸；网络均为模拟。
- 前端：新增十个场景，合计三十八个账号、台账、流转及附件场景通过；实际二维码图片识别、打印 PDF 单号提取、双页原件预览、上传重试、人工核对、更正及失权清除均在本地浏览器验证。

这些检查不等于 Supabase Edge Runtime、真实 Storage、纸张签字或大陆访问验收。尚未上传三张演示单的未签字 PDF，未伪造签名、核对或归档结果。

## 待授权的上线范围

1. 重新保存共享配置、元数据及业务基线，确认文件规则和此次原件保留方式。
2. 应用迁移 007；仅设备簿五个新列、十八个新函数、新触发器及事件类型约束变更。
3. 先安装只约束目标桶的客户端隔离策略，再通过 Storage API 创建私有桶，限制 20 MiB 和三种 MIME；不修改其他桶。
4. 新增专属函数所需的桶名、前端 origin 和开启值，复用平台内置凭据；同名变量若已存在则先核对，不覆盖不相关配置。部署独立函数，保持其他函数代码和认证邮件设置不变。
5. 通过既有 CI/CD 发布并开启独立附件开关，检查匿名、未准入与当前角色的限制；网站 CD 仍不自动迁移数据库、创建桶或部署此函数。
6. 实际有签字原件后，再单独验收上传和人工核对归档；未经真实核对不归档示例文件。

本轮尚未执行以上云端写操作。回退入口时关闭前端独立功能开关并发布；如需停止原件上传与下载，同时关闭函数侧开关。保留原件、关联、单号及审计，避免删除列或清空桶。真实地址、资源标识、凭据及原始核对记录仅保存在私有环境。
