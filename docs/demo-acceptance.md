## 本人操作顺序

1. 实际登录，进入“单据记录”，打开已有的演示分发单。核对三件原始明细、负责人和期限；再到台账查看一台已退回、两台仍使用的当前情况。
2. 从详情打印或使用本轮保存的实际 PDF，检查纸上单号、长编号、页码、二维码和签字栏。完成纸质签字；记录打印机、浏览器及是否有截断或缺字。
3. 回到同一单据，上传签字照片或扫描 PDF。等待原件保存成功，核对识别单号和候选单据；识别失败时按页面提示人工关联，不把识别成功当作签字已经核实。
4. 打开预览并下载一次，核对原件、签字、设备及双方内容、页数和关联单号。确认四项人工核对后再归档；上传本身不代表归档。
5. 重新打开单据，确认归档状态和原件仍可读取，台账去向未因打印、上传或归档变化。导出附件关联清单，核对刚上传的文件名、对应单号及核对状态。
6. 实际导出设备与单据 CSV，在 Excel 中使用“从文本/CSV”导入，将编号与序列号列设为文本，核对前导零及中文。
7. 若已有查询人账号，用它验证单据、原件和清单可读，办理及更正入口不可写。没有可用账号则保持待验收，不为凑结果批量注册账号。

完成后反馈“已上传”或“已归档”及发现的问题，后续再只读核对实际记录；未收到原件和本人核对结果前，不把签字闭环标记为通过。

## 后续演练与邮件数量

本轮先使用已有演示单，不重复生成一批交接记录。转交、延期、故障维修等真实登录演练，以及需要新写演示业务的场景，应先列明选定设备、接收对象、步骤与预期结果，再单独确认写入范围；不能把虚构 API 回归算作已办理真实业务。

本轮邮件实发为零。后续确需验证通知时，先安排一次小范围检查，最多两封，限定已授权的测试收件人；不重复发送全套模板，不为测试反复注册或找回密码。现有六位验证码及密码找回已由本人确认的结果继续保留，站内到期查询不代表到期邮件已实现。
