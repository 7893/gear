# 故障登记与维修恢复

状态：迁移 011 已获授权应用，页面随本轮既有 CI/CD 发布；云端权限、匿名拒绝及只读查询核对通过。真实故障登记和维修恢复待本人验收；当前生产进度统一见[实现状态](implementation-status.md)。

## 使用方式

管理员或经办人在设备详情页操作。正常的在管有效设备显示“登记故障”；故障设备显示“恢复正常”。填写实际发生日期，以及故障说明或维修处理结果，最多两千字。默认日期为东八区当天，允许按实际情况修改。

每次操作只处理当前设备。库存、个人、团队和临时使用均支持，设备编号、旧编号、持有方、负责人、位置、分配身份、期限及跟进人保持不变。故障不等于退回；实际交回时使用既有退回单。修好后沿用原设备，不重新建账。已退上游、遗失、报废或误建无效设备不能通过此入口恢复管理。

故障和维修是设备事件，不生成交接单或占用正式单号；也不伪造签字件。历史中显示实际日期、UTC 记录时间的东八区展示、操作者及说明，快照保留当时持有关系。没有新增维修工单、维修费用、配件或审批流程；事件证明附件、资料更正和退出管理仍待后续范围。

## 日期与冲突

实际日期必须有效且不晚于东八区业务当天，不能早于最近交接、当前已知领用起始日期或已登记的故障、维修日期。未知历史日期继续留空，不以建账时间补造起始日。同一天的先后按不可改写事件顺序记录；不允许将新恢复记录倒插到故障之前。

故障或维修不改写 `last_flow_on`，它继续表示实际交接日期。确认领入、分发、转交或退回时同时核对最近故障、维修日期，禁止用新草稿将交接倒插到设备当前状况之前。该限制也适用于同团队负责人交接。日期错误需要核对后更正，当前入口不提供管理员绕过。

提交前核对设备版本；状况变化推进版本，之前保存的交接草稿需重新核对设备。多人同时操作仅一个当前版本成功；其他人保留表单并提示刷新。故障设备继续不能正常分发或普通转交，既有团队负责人交接保留实际故障，实际故障退回仍可办理。

网络超时后填写内容保留，当前表单内相同内容使用同一请求标识重试，只记录一次；重复请求返回最初快照。请求内容或操作者不同则冲突。刷新或离开页面后不承诺继续保留请求标识，结果不明时先刷新核对历史，不盲目再登记。

## 数据库和页面复用

[迁移 011](../database/migrations/202610190011_asset_condition.sql)只新增一组 `change_asset_condition(asset_id, expected_version, target_condition, occurred_on, reason, request_id)` 公开与私有函数，并扩展既有私有 `confirm_document` 的日期检查。旧确认函数体指纹不匹配或迁移重跑即整体失败，不覆盖未知部署变更。保留现有函数身份、所有者和授权，不增加业务表、列、触发器或事件类型。

继续使用既有 `asset_fault_reported`、`asset_repaired` 事件及设备版本触发器。事务顺序为设置单行锁、当前有效身份与写角色、请求去重、设备锁及版本、状态和日期核对、更新状况、保存前后快照与事件。权限检查先于重试返回，已失权账号不能重放旧请求取得结果。

仅 `authenticated` 可调用，实际仍需已验证邮箱与启用的管理员或经办人成员身份；匿名和服务角色没有新增执行权。查询人通过原 `get_asset` 和台账读取，不能写入；不存在直接写表或由客户端指定操作者的路径。

页面使用独立 `AssetConditionForm.vue` 接入原设备详情，复用 `inventoryRpc`、权限判断、中文错误、请求标识和 `ActionGroup`。不增加页面路由、依赖、运行开关或机密。保存成功重新读取详情及事件，失权或离开后的迟到响应不能重新显示旧设备。

## 检查及发布边界

[隔离数据库检查](../database/tests/check_asset_condition.py)覆盖迁移对象及数据保留、重跑拒绝、库存及个人团队持有、故障与恢复、期限和原编号保持、相同请求并发重试、不同请求竞争、失权重放拒绝、无效状态、非法日期、旧草稿冲突、补录日期回滚、故障退回及维修恢复、旧正式快照冻结；只使用临时 PostgreSQL 和虚构身份。该脚本已加入 CI。

浏览器新增四个虚构 API 场景，检查故障与恢复、响应丢失重试及历史、日期边界和表单保留、无效设备与失权隐藏，以及查询人只读。全部五十三项浏览器检查、格式、类型及构建通过；故障、既有流转与转交的隔离数据库检查通过。通过检查不等于生产已登记真实故障或完成维修验收。

本轮已获单独授权应用迁移 011 并推送触发既有 CI/CD。迁移前保存生产只读基线，迁移后确认仅新增两项函数并扩展一项私有确认函数；原函数对象身份、权限、设备、使用分配、单据、编号序列、共享 Auth、文件服务和其他应用保持。使用有效管理员在只读事务中核对设备详情、历史与到期查询，匿名写入口拒绝通过；没有创建故障或维修业务记录。现有 CD 不执行数据库迁移。

本轮不发送邮件，不创建故障演示记录，不办理真实退回，也不修改 Auth、Storage、域名、证书、其他应用或凭据。生产基线、资源标识和部署参数只放在忽略的私有记录中。若需撤下入口，通过代码回退发布；保留业务数据与不可改写事件，不能用删除记录回退。
