# 审核邮件通知接入

状态：本地实现及隔离检查已完成，迁移 004、独立发送器和专用调度已获授权部署；管理员状态区通过既有 CI/CD 发布，通知开关按页面验证后开启的顺序启用。真实新申请和审核结果收件待本人验收。账号注册和密码找回已由本人确认可用；本次仅补齐新申请提醒及通过、拒绝后的审核结果通知。

## 业务行为

账号事务仍在保存申请或审核时登记待发任务，页面不等待 Gmail。新申请提醒发送给登记任务时的管理员，发送前再次要求该收件人仍为有效管理员、邮箱已验证，申请人仍处于相同版本的待审核状态。不会把旧任务改投给后来新增的管理员。

通过或拒绝的结果发送给申请人当前已验证的邮箱。通知对应的审核事件、成员版本及当前状态必须一致；已经停用、改角色、恢复待审核或再次审核的旧任务取消。收件人和通知内容由数据库根据真实成员与事件解析，队列 `payload` 中的邮箱、角色或模板不能覆盖它们。

发送前领取一次任务，刷新 Google 授权后再次核对发送条件。第二次检查之后仍可能发生并发审核变更；已经提交给 Gmail 的邮件不能撤回，页面及邮件均提示以系统当前记录为准。

启用时记录当前 UTC 时间，只处理此后创建的新任务；此前任务取消，不默认补发历史通知。重新开启会建立新的时间边界。停用通知不撤回已开始提交的邮件。开启和关闭仅允许部署者通过拥有者函数执行，并登记设置审计。

## 数据库与权限

[迁移 004](../database/migrations/202610180004_notifications.sql) 为设置增加启用时间，为已有待发表增加任务令牌和提交开始时间；不创建独立队列，也不改变共享 Auth 或其他应用业务表。

| 接口 | 权限与用途 |
| --- | --- |
| `gear.claim_account_notification()` | 仅 `service_role`，领取一个审核通知任务并签发处理令牌 |
| `gear.prepare_account_notification(job_id, token)` | 仅 `service_role`，重新核对资格，并只返回一次当前收件人和固定类型内容 |
| `gear.finish_account_notification(...)` | 仅 `service_role`，凭令牌登记已提交、明确失败或结果不明 |
| `gear.notification_status()` | 已登录有效管理员，读取计数和最近二十项处理状态；不返回收件邮箱、正文、令牌或邮件服务原始响应 |
| `gear_private.configure_account_notifications(enabled)` | 仅数据库拥有者，设置通知开关、启用边界及审计 |

服务端没有新增直接读写业务表、读取 Auth 用户表或执行其他业务函数的权限。内部函数固定空 `search_path`，服务角色只能访问明确授予的接口。匿名、普通成员不能领取、完成任务或更改发送开关。

账号管理页增加一个通知状态区。显示待发送、处理中、已提交邮件服务、失败、结果不明和取消；错误仅显示固定中文分类。通知状态读取失败不阻止已获授权的账号审核；失去管理员权限后清空并隐藏通知状态。

## 发送与失败处理

[notifications.ts](../supabase/functions/gear-auth-mail/notifications.ts) 为独立发送器；[notification-index.ts](../supabase/functions/gear-auth-mail/notification-index.ts) 是入口，部署为新的 `gear-notification-mail`。与认证 Hook 共用源码目录、中文模板及 MIME 编码，但不替换 `gear-auth-mail`，不更改共享 Hook 或项目安全通知。

发送器仅接受独立 `GEAR_NOTIFICATION_TOKEN` 的后台调用，没有浏览器跨域入口。调用者不能指定收件人、邮件内容或任务编号；每次最多处理一个任务，全项目设备簿审核通知同时最多处理一个任务。请求中断后不会在同一次调用中重新发送。

任务租约为两分钟，完成回执必须匹配令牌；旧实例不能覆盖后续任务的结果。租约过期转为结果不明，不自动重新领取。Gmail 返回有效邮件编号才记为“已提交邮件服务”，这不代表已送达。

OAuth 临时故障、明确的授权拒绝或邮件服务限流允许延后重试；授权失效等永久错误停止自动处理。退避至少一分钟并逐次增加，兼顾 `Retry-After`，单次延后不超过一天，每个任务最多尝试五次。Gmail 超时、连接中断、服务端错误或缺少有效邮件编号均保守记为结果不明，不自动补发。

按东八区自然日设置五十次业务通知处理保护，重试也计入；跨日重试会保守计算该任务以前的尝试次数。此保护不是邮箱配额，也不涵盖独立的认证邮件。未知结果、永久失败或达到重试上限需要维护者核实，当前不提供会导致重复邮件的自动重发或人工重发按钮。

## 调度与私有配置

采用 Supabase Cron 每分钟检查一次队列，经 `pg_net` 调用新发送器，Vault 保存专用函数地址和调用令牌。没有合适任务或开关关闭时不发起 HTTP 请求，不为此增加外部队列或另一家服务。

[调度安装脚本](../database/schedule_account_notifications.sql) 由部署者单独执行，不随迁移或网站 CD 运行。脚本检查扩展、命名冲突及配置，仅建立 `gear-account-notifications` 一个任务及两个 `gear_notification_` Vault 项；不会自动安装扩展或开启发信。重复安装安全失败，先核对已有资源，不覆盖同名任务或机密。

部署前只读检查确认现有项目具备 Vault，`pg_cron` 已预加载，两项调度扩展可用但未安装。用户明确授权共享影响后，已安装 `pg_cron`、`pg_net`，并建立设备簿的专用调度和私有配置。扩展版本和真实资源信息仅保存在私有检查记录。

`GEAR_NOTIFICATION_TOKEN` 只用于新发送器和调度调用；平台内建服务凭据只在函数内用于固定 RPC。继续复用既有 Gmail 凭据，不申请新邮箱权限，也不把发信凭据加入网站构建。真实地址和专用令牌保存在忽略的项目配置、权限为仅当前用户可读写的凭据文件、平台机密及 Vault 中。Cron 命令仅引用固定函数名；`pg_net` 的内部请求队列处理请求头，不能把该队列当作公开日志或公开查询接口。

## 上线顺序与回滚

本次已获用户明确授权，按以下顺序上线：

1. 应用迁移 004，核对函数授权、原有成员及业务数据不变，发信仍关闭。
2. 添加一项专用调用令牌，部署新的 `gear-notification-mail`，验证无令牌拒绝及开关关闭时空闲返回；不发送验收邮件。
3. 启用此前未安装的 `pg_cron`、`pg_net`，通过公开脚本创建本项目的 Vault 配置和每分钟调度，核对其他资源未被覆盖。
4. 发布管理员通知状态区，再由拥有者函数开启审核通知并记录审计及启用边界。此后真实的新申请、批准及拒绝可触发邮件，实际收件由本人验收。

关闭时先调用拥有者开关函数，再只停用本项目的 Cron 任务；保留任务、审计及未知状态，不删除其他项目的任务或共享扩展。不要通过禁用整个 Cron 扩展回滚，因为这会删除该扩展承载的全部任务。

本地检查包括九项发送器用例、既有认证邮件回归、一次性 PostgreSQL 的权限、并发、资格变化、令牌、回执、重试及限额检查，以及浏览器的管理员状态显示、读取失败与失权清理。调度派发函数已使用隔离的 Vault 和 HTTP 替身检查。线上已核对无令牌拒绝、合法令牌空闲返回、专用调度与 Vault 摘要、最小权限及关闭时不发起 HTTP。原有数据库对象、业务数据、Auth/REST 配置、机密值摘要和其他函数代码及 JWT 配置保持不变；平台新增机密时自动提升旧函数版本元数据。真实新任务经定时调度发送及实际收件仍待本人验收。到期汇总、停用与恢复通知、密码变更通知仍不在本次发送范围内。
