# 临时使用延期与到期查询

状态：已获授权上线，迁移 009 已应用正式数据库；页面通过本轮既有 CI/CD 发布。现有签字件的真实用户验收状态不因此改变。

## 本轮行为

- “临时使用与到期”列出当前仍在管的临时领用设备，可按已逾期、今天到期、即将到期、尚未临近筛选，按期限和设备编号排序。
- 到期当天不算逾期，次日才算。服务端计算东八区业务日期；临近天数读取既有设置，初始值为三天。页面显示实际日期和天数，不按浏览器时区重新分组。
- 列表默认每页二十条，可选十、二十、五十或一百条；查询和更改页大小回到第一页。仅对当前授权结果在页面内分页，适合不到一百件设备的规模。
- 管理员和经办人在设备详情为一台设备办理延期，填写新期限和原因。新期限必须晚于原期限，且不早于东八区当天。查询人只有读取权限。
- 同批设备可分别延期，未选择的设备保持原期限。长期使用、已退回、退出管理或无效建账设备不能通过延期入口修改。
- 历史显示原期限、新期限、原因、经办人及记录时间；延期不生成交接单，不取号，不改写原分发单、明细快照或签字原件，不改变原跟进经办人。

本轮提供站内查询和逐设备延期；没有批量延期表单、归还提醒邮件或新定时任务。后续邮件可复用当前分配与期限，不从旧单据快照推算当前到期日。

## 数据与权限

[迁移 009](../database/migrations/202610190009_temporary_use.sql)仅新增两组函数，不增加表、列、触发器或事件类型。使用已有 `assignment_extended` 事件及当前分配记录。

`list_due_assets(state)` 返回服务端业务日期、实际临近天数、符合条件的设备与全局临时领用统计。只纳入有效且在管设备的当前未关闭临时分配；库存、长期使用及已结束分配不参与统计。筛选不改变统计口径。

`extend_assignment(asset_id, expected_version, new_due_on, reason, request_id)` 先按既有交接顺序锁定单行设置，再核对当前账号、请求重放、设备版本和有效临时分配；整笔事务更新期限、推进设备版本并保存不可改写事件。日期严格接受公历 `YYYY-MM-DD`，原因必填且不超过两千字。服务角色与匿名角色均无执行权；每次调用重新检查本应用审核、角色及邮箱验证。

相同账号和相同内容的请求重试返回原结果，不重复延期；同请求标识更换内容或账号会拒绝。并发修改同一版本只有一项成功。设备版本推进后，旧页面及尚未确认的交接草稿必须重新读取核对，不得覆盖新期限。页面在网络失败时保留输入和请求标识；冲突时可通过“刷新设备情况”重新读取。

## 验证与上线

[数据库隔离检查](../database/tests/check_temporary_use.py)覆盖东八区日期及临近边界、既有天数设置、权限与停用、重复和并发请求、部分延期、历史留痕、单据冻结、旧退回草稿冲突及实际退回结束查询。

[浏览器检查](../web/tests/inventory.spec.ts)使用虚构账号与接口，覆盖延期网络中断后重试、无效日期、版本冲突保留输入、查询人无写入口，以及到期列表分页、筛选与空结果。本轮共四十五个浏览器场景通过，包含账号按钮间距和公共分页回归；正式库权限、匿名拒绝及有效管理员只读查询已核对，真实登录延期仍待本人验收。

本轮已按单独授权先保存云端基线、执行迁移 009 并核对权限及只读结果，再通过既有 CI/CD 发布页面。原有五十一台设备、三张单据、编号、分配、签字件及共享配置保持不变；上线检查没有办理业务延期。网站 CD 不执行 SQL。后续类似更新仍须先完成对应迁移，再发布依赖它的页面。

本轮不更改共享认证、邮件、存储桶、凭据或其他应用。正式业务延期须由本人操作或另行明确指定演示设备；技术上线不会自动延期现有设备。真实地址、资源标识、操作者和云端原始检查仅保存在已忽略的私有记录。

回退页面时发布前一版本，保留迁移和延期事件，不通过清空历史或倒改期限回退。正式数据更正需要后续受控业务规则，不能直接改写审计。
