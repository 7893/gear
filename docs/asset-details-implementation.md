# 设备基本资料更正

状态：已完成本地实现，全部八十七项前端检查、格式、静态检查、类型检查及构建通过；新增隔离数据库检查与建账、流转、单据处理回归通过；迁移 013、推送及生产发布待单独授权。打印、纸张签字及对应验收按用户最新决定暂缓，本轮优先补日常业务。统一进度见[实现状态](implementation-status.md)。

## 操作范围

当前有效管理员和经办人在设备详情打开“更正基本资料”，更正名称、分类、原资产编号、出厂序列号、品牌、型号、位置和备注，填写最多两千字的更正原因。查询人只读，已标记无效的建账记录不允许更正。

在用、在库和已退上游、遗失、报废设备都可核对描述性资料；修改不重新纳管。内部编号与设备身份永久保留，持有方、负责人、实际状况、分配身份、未知起始日期、期限及最近交接日期保持不变。去向、延期和故障继续使用各自已有业务入口。

旧编号保留原始格式及前导零；当更换旧编号且与其他设备去除首尾空格后的旧编号相同时，先提示，再由经办人确认确为不同实物。不自动合并设备，也不因修改名称而再次要求确认本就重复的旧编号。

完全没有资料变化时不新增更正。历史显示经办人、记录时间、原因和各字段前后值；正式单据的明细、双方、抬头及签字原件不被重写。

## 复用与页面

建账与更正共用 [AssetFields.vue](../web/src/components/AssetFields.vue) 和字段默认值。建账的实际状况通过组件插槽保留，持有情况仍属建账业务；更正表单不出现这些可改变去向或状况的字段，不分别复制一套基本资料输入。

[AssetDetailsForm.vue](../web/src/components/AssetDetailsForm.vue) 复用公共按钮组、中文错误和相同内容重试的请求标识。失败保留表单；旧编号改变后撤销旧确认。成员、角色、设备或版本变化及页面退出会使旧响应失效。保存后由详情重新读取，台账和新清单显示新资料，原单仍显示确认时快照。

## 数据库与一致性

[迁移 013](../database/migrations/202610190013_asset_details.sql)只新增两层 `update_asset_details(asset_id, expected_version, details, reason, request_id, allow_legacy_duplicate)` 函数，不增加表、列、触发器或依赖，不更改既有函数、权限和共享配置。迁移在事务内执行，重跑或名称冲突时失败，不覆盖已存在函数。

服务端白名单只接受上述八项字段的完整资料对象，拒绝夹带内部编号、状态、持有关系、期限或版本等字段。执行前取得现有设置单行锁，核对当前写权限，再查请求结果并锁定设备、检查版本及无效标记；与交接、延期、故障及角色变化采用既有锁顺序。并发更正同一版本只有一次成功，相同请求重试返回首次保存结果；角色失效后不能借旧请求继续操作。

使用既有 `asset_updated` 事件保存完整前后快照及原因，不把资料更正标为真实流转。`after_data.previous_details` 提供八项旧值，供原历史读取接口展示差异；不增加另一套读取接口，幂等 RPC 返回原保存的设备结果。时间点继续存 UTC，审计自然日由服务端按东八区计算。

设备版本递增会阻止旧草稿继续确认，需要重新读取设备并核对。作废仍遵守已有状态和依赖检查：后续名称、型号更正不被撤销；位置与原单结果冲突则整单拒绝作废。设备编号序列、单据流水、原始分配及正式快照不因更正变化。

## 检查及待完成事项

[隔离数据库检查](../database/tests/check_asset_details.py)验证迁移及权限保留、匿名和服务角色拒绝、白名单与长度、重复旧编号、无效记录、无变化与旧版本、当前角色、原结果重试、并发修改、分配及正式快照保留、旧草稿拒绝和作废衔接；已加入 CI。全部使用一次性本地 PostgreSQL 和虚构身份，不访问生产数据库。

前端新增八个虚构接口场景，覆盖两种写角色、响应丢失重试、历史前后值和转义、重复编号确认及撤回、冲突保留输入、查询人及无效记录无写入口、退出管理后仅改资料、失权与离开后的迟到响应；建账的既有场景同时验证公共字段组件。

人员团队修改停用、遗失报废及找回入口、单位抬头设置和到期邮件仍在后续业务阶段。真实资料更正待本人实际操作验收，本轮不更正任何生产设备；需单独授权后应用迁移 013，再推送通过既有 CI/CD 发布页面，网站 CD 不执行 SQL。实际环境值与资源标识继续只存忽略的私有记录。
