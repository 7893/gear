# 到期提醒频率调整

2026-10-20 用户要求降低频率：按配置提前天数提醒一次，到期当天一次，逾期仍未处理则每隔三天提醒一次。默认提前三天；例如 25 日到期，提醒日为 22、25、28、31 日，再按实际日历日期每隔三天继续。

## 规则

- 以每台设备当前临时分配的预计归还日期为基准，逾期首次提醒为到期后第 3 天，此后第 6、9、12 天等；提前天数为 0 时与当天合并。
- 按东八区业务日计算，含周末；按管理员设定时间处理。错过的历史节点不补发，开启晚于提前节点时等待下一个节点。延期后按新日期计算，归还或退出管理后不再提醒。
- 同一经办人、同一业务日仍最多一封汇总；邮件仅统计当天到达节点的设备，未到节点的其他逾期设备仍完整显示在站内清单。不同设备的节点可能分布在连续日期，因此不承诺同一人所有邮件之间都相隔三天。
- 继续沿用既有收件人资格、管理员兜底、队列去重、租约和结果不明不盲重发规则。开关及提前天数、时刻均不由本迁移更改。

## 实现与验证

新增追加迁移 022，仅替换公共内部筛选函数 `due_notification_counts`。入队与发送前复核都复用该函数，不在页面或发送器各写一遍频率判断；不改已上线的迁移 021，不增加表、字段、云产品或调度任务。内部通知类型 `daily_due` 保持，页面和邮件说明改为节点提醒。

隔离检查覆盖 67 个日期位置、提前 0/1/5/30 天、发送前延期重算、同人同日去重、多设备合并、已处置设备排除、不同服务器时区及迁移对数据和权限的保留。另核对设置页面与原业务通知回归，无真实邮件。
