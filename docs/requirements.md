# 需求与范围

## 已确认

### 使用场景

- 项目名称：设备簿 / gear；本地项目目录名为 `gear`。
- 个人经办或小型单位内部使用，组织规模约一百人，保持轻量。
- 当前各类设备合计几十件，预计不到一百件；设备数量、组织人数、系统用户数分别统计，不混为同一规模。
- 存量设备一部分由经办人持有，一部分已发给个人或团队；首次建账需覆盖这些现状。
- 经办人批量领回电脑、打印机等设备，再分配给组织、团体或个人。
- 管理从设备到手到日常流转、损坏退回的全过程，不只是存单据。
- 支持借调、挂职、临时人员使用一段时间，以及人员变化后的动态分配。
- 第一版逐件管理打印机、饮水机、台式电脑、笔记本电脑、电插板、碎纸机、智慧屏等设备，不纳入纸张、硒鼓等耗材。
- 团体领用必须登记接收负责人，具体使用人可以后补。
- 临时使用填写预计归还日期，支持延期，并通过系统内提示和邮件提醒到期归还。

### 台账与查询

- 现有设备部分有编号、部分没有；历史编号规则不统一，不能强制套用一种格式。
- 建立设备台账，查询每件设备的当前状态、持有人和去向。
- 业务确认后及时更新台账，保留历次分配与退回记录。
- 支持查看可分配设备、已发出设备及各接收对象名下设备。
- “实时”指已登记业务及时反映在系统中，不代表自动探测设备故障或物理位置。

### 使用与交付边界

- 通过互联网使用，系统用户不到十人或十来人，按约十名用户设计。
- 中国大陆普通网络需能访问完整系统，不仅是首页；覆盖登录、台账、上传、预览、下载及邮件操作链接。
- 用户已有自有域名，后续使用其指定域名或子域名；真实域名仅在私有配置或运维记录中维护，DNS 变更须单独授权。
- 系统用户数量与约百人的设备使用组织规模是不同概念。
- 允许使用云服务；托管与存储平台已确定，识别服务待后续选择，实际接入进度见技术记录。
- 以电脑操作为主，手机支持查询和拍照上传。
- 项目代码公开开源；业务数据、签字附件和凭据不属于公开源码内容。

### 账号与权限（已确认）

- 每人独立账号，采用管理员、经办人、查询人三种固定角色，不做自定义权限配置。
- 管理员：账号与角色管理、全部业务操作、正式单据作废与更正、系统设置。
- 经办人：设备录入、领入、分发、转交、退回、打印、上传及核对签字件，可修改草稿。
- 查询人：查看台账、状态和流转记录，不能修改数据。
- 第一版三种角色均可查看全部台账，不按个人或部门限制设备可见范围。
- 正式确认后的单据不能随意修改，作废与更正由管理员处理并留痕。
- 记录操作人；停用账号后保留其历史操作记录。
- 权限由后端校验，页面控制不能替代后端授权。

### 注册、通知与运行要求（已确认）

- 开放注册，注册后须经管理员审核通过才能访问业务数据和功能。
- 使用账号密码登录，支持修改密码和管理员重置密码。
- 采用邮箱加密码登录，先验证邮箱再由管理员审核，审核默认查询人；首次管理员由部署者初始化，密码找回不绕过审核或停用，具体流程见[账号与访问流程](account-design.md)。实际认证参数与已上线范围见账号实施记录。
- 支持注册、日常通知和提醒邮件；已选用自有域名 Google 邮箱通过 Gmail API 发信，完成独立的授权、令牌刷新和同域实际收件验证；注册与找回已上线并由本人确认成功，审核通知已启用；真实新申请审核及收件仍待验收，详见[邮件与通知设计](email-design.md)。
- 按最新决定简化备份：短期可暂不启用，后续按需手动整体导出；本地留存或放入私有对象存储均可。早期每日自动备份、30 天恢复点及一天数据损失窗口不再作为当前要求。
- 电脑操作为主，手机支持查询和拍照上传；复杂管理、批量操作和打印优先适配电脑。
- 最新选型目标是尽量零新增费用，优先免费能力和复用现有资源；当前选择 Supabase 免费版与 CloudFront Free 套餐。
- 早期允许部分云平台小额付费的讨论保留为历史背景，不代表已经订购付费服务。Oracle 若后续使用仍限永久免费资源。
- 当前分工：开发机负责开发与构建，现有美国主机通过 Nginx 托管前端，CloudFront 分发网站，亚太 Supabase 提供 Auth、PostgreSQL、Edge Functions、Storage 和 Cron。后台入口使用另一自有域名的子域名，Cloudflare 后端网关已接入并通过开发机真实浏览器链路检查；详见[技术选型与部署记录](technical-proposal.md)。
- 已确认共用现有 Supabase 项目；设备簿独立维护业务数据、成员审核与角色。共享 Auth 用户不自动获得设备簿权限，设备簿停用不全局封禁账号；共享密码及项目级认证配置的跨应用影响须在实施时核对。
- 代码公开开源已确认，具体许可证尚未选择。
- 系统时间点统一使用 UTC，显示、业务日界及提醒按东八区计算；实际交接日期和预计归还日期等纯日期字段保持日期语义，不作为 UTC 时间点转换。

### 流转与凭证

- 支持批量领入、分发、常规转交与退回，故障设备可退回。
- 领入和分发均需要单据；常规流转统一保留相应凭证。
- 单据有编号，可打印后线下签字。
- 签字件可上传并识别，关联电子记录，实现交接凭证闭环。
- 故障设备可退回经办人，也可直接退给上游，按实际交接记录接收方。
- 识别范围先限定为单号匹配，人工确认后归档，不自动判断签名真伪。
- 允许上传交付方已有的领入单据，保留外部单号并关联内部记录。
- 使用通用 A4 打印模板，单位名称可设置。

## 第一版建议边界（待确认）

- 支持约十名系统用户按已确认角色协作，设备接收人无需全部注册账号。
- 包含台账、流转办理、单据与签收附件、状态查询。
- 批量录入、导入导出、打印和附件回传优先采用简单操作。
- 不引入复杂审批、财务折旧、采购管理或自动硬件监控。
- 按已确认范围逐件管理设备，电插板等无出厂序列号的设备也可使用内部编号追踪。
- 备份按最新决定保持轻量；手动整体导出需要覆盖网站交付文件、数据库与附件，具体工具尚未实现。

## 设计原则

- 一次办理流转，同时更新台账和生成凭证，避免重复填账。
- 设备当前情况与历史记录同时保留。
- 设备状态与签字件归档状态分开，避免未上传附件就无法记录实际去向。
- 识别结果需核对，不能将识别到手写签名等同于验证签名真伪。

## 补充业务需求（已确认）

- 遗失、报废等退出管理记录原因、日期和经办人，保留设备历史，不直接删除设备；系统记录处理结果，不新增报废审批流程。
- 团队负责人更换时办理责任交接，团队可以不变，历史单据保留原负责人。
- 电源适配器、遥控器等附件记录在设备备注和交接明细中，第一版不单独建立配件台账。
- 支持按个人或团队导出持有清单供现场核对，第一版不增加独立盘点模块。

## 非功能需求（已确认）

- 常用操作保持简短；提交失败保留填写内容；重复点击不能重复开单。
- 在中国大陆实际使用网络验证登录、查询、上传下载、验证码及邮件链接；前端境外托管，使用自有域名，不采用大陆主机托管前端。
- 多人同时分发同一设备只能有一次成功，冲突需明确提示，不能产生部分静默成功。
- 明确图片和 PDF 的大小、页数及格式限制；长编号完整显示，多页打印不能拆开签字区。具体限制数值尚未确定。
- 待审核和停用账号不得读取业务数据；修改、作废和归档记录操作人及时间。
- 短期不要求自动备份或固定恢复窗口；启用手动导出与恢复后，验证台账、账号权限与附件可用，不能以导出成功代替恢复验证。
- 上传、识别、邮件以及启用后的手动导出失败应可发现并重试，不能静默失败；外部服务失败不得回滚已完成的真实交接。
- 支持导出台账、单据记录及附件关联清单，便于数据迁移和留存；附件原件也需有授权导出路径。
