# 页面、字段与单据草案

状态：字段与交互设计，不包含应用实现；业务规则以[统一业务规则](business-rules.md)为准，不继续制作样稿。

分发、转交、退回共用表单的字段与处理规则见[日常操作设计](daily-operations.md)。

## 页面结构

三个日常入口保持不变，账号管理放在管理员专用设置中。

| 页面 | 默认内容 | 主要动作 |
| --- | --- | --- |
| 设备台账 | 搜索框、状态统计、设备列表 | 领入、选择设备分发、查看详情、导出 |
| 流转办理 | 领入、分发、转交、退回四个入口；未完成草稿 | 新建、保存草稿、核对并确认 |
| 单据记录 | 单号、类型、日期、双方、数量、凭证状态 | 查看、打印、上传、核对；管理员作废或更正 |
| 我的账号 | 姓名、邮箱、角色、账号状态 | 修改密码、退出 |
| 管理设置 | 待审核账号、已启用账号、单位名称 | 审核、分配角色、停用账号、修改打印抬头 |

首页直接进入台账。统计按在库可用、在库故障、使用中、已退上游、遗失、已报废六类互斥汇总；在管故障数量单独展示，不重复加进总数。另列到期/逾期和待回传签字件提醒。

台账默认列：设备编号、名称、型号、状态、当前持有方、负责人、位置、预计归还日期、操作。型号和位置缺失时显示“未填写”，不编造默认值。手机以卡片或精简列呈现，保留查询和上传。

设备详情分为“当前情况、流转记录、关联凭证”。点击历史单号进入对应单据。查询失败显示重试入口，不能显示为零台；无设备时提供“登记已有设备”和“新领入”两个入口。

## 台账字段

当前设备总量几十件、预计不到一百件。优先简单表格录入与查询，不因支持批量操作而引入复杂仓库层级或大批量迁移流程。

| 字段 | 要求 | 说明 |
| --- | --- | --- |
| 内部设备编号 | 系统生成、唯一 | 稳定标识每件设备，不使用旧编号作为内部唯一键；格式待定 |
| 原资产编号 | 选填 | 按原样保存既有标签编号，不要求统一格式；无编号时留空 |
| 分类 | 必填 | 打印机、饮水机、台式电脑、笔记本电脑、电插板、碎纸机、智慧屏、其他 |
| 名称 | 必填 | 可由分类提供默认名称后修改 |
| 品牌、型号 | 选填 | 不为电插板等简单设备强制填写 |
| 出厂序列号 | 选填 | 不作为所有设备必填字段；与内部编号区分 |
| 管理状态、当前持有方、状况 | 系统维护 | 通过流转更新，不能直接覆盖以绕过交接记录 |
| 位置 | 选填 | 楼栋、房间或简单位置描述 |
| 来源批次 | 系统维护 | 新领入关联首次领入单；存量建账关联建账记录，未知历史来源留空 |
| 备注 | 选填 | 附件、电源适配器、外观等说明 |

领入同型号多件设备时允许填写数量，系统展开为逐件编号明细，确认前可逐件补序列号。设备实际记录一件一条，不能只保留数量导致后续无法部分退回。

### 混合历史编号（设计建议）

用户已确认既有编号不齐全、历史规则不统一。建议每件设备均生成稳定内部编号，原资产编号独立保存，既有实物标签无需全部重贴。

- 原资产编号按文本保存，保留前导零、字母、汉字及分隔符，不强制改写格式。
- 搜索支持内部编号、原资产编号和出厂序列号；台账和单据显示内部编号及有值的原编号。
- 无原编号时留空，不使用“无”等占位文本作为编号。
- 原编号重复时提示并展示来源、型号和持有人供核对；不自动合并，不假定旧编号全局唯一。
- 确认为同一件已建档设备时复用原台账，记录新的流转，不能再建另一件设备。
- 补录或纠正原编号不改变内部编号，修改留痕；已确认单据保留当时编号快照。
- 导入模板区分内部编号、原资产编号和序列号；首次导入生成内部编号，后续更新优先按内部编号匹配，不凭重复旧编号覆盖。

## 接收对象与使用期限

| 字段 | 个人领用 | 团体领用 |
| --- | --- | --- |
| 接收对象 | 姓名必填，内部标识区分同名 | 团体名称必填 |
| 接收负责人 | 个人本人 | 必填，作为本次交接责任人 |
| 所属单位 | 选填 | 选填 |
| 人员类型 | 本单位、借调、挂职、临时 | 具体使用人补录时可填写 |
| 联系方式 | 选填 | 负责人联系方式选填 |
| 使用期限 | 长期或临时；临时填预计归还日期 | 同左 |
| 具体使用人 | 本人 | 可后补 |

团体仍是持有方时补填内部使用人不虚构另一张交接单；实际持有方改变则办理转交。历史单据保存当时负责人和名称快照，联系人资料变化不能改写已打印单据。

## 流转表单与交互

### 首次登记已有设备（建议）

与“新领入”分开提供“登记已有设备”入口，直接建立当前状态，不虚构历史交接。

| 当前情况 | 登记内容 |
| --- | --- |
| 在经办人手里 | 设备名称、分类、已有编号（如有）、正常或故障；位置选填 |
| 已发给个人 | 上述设备资料、当前个人使用人；临时使用补预计归还日期 |
| 已发给团队 | 上述设备资料、团队名称、接收负责人；具体使用人可后补 |

- 系统生成内部设备编号和建账记录，记录建账时间与经办人，不生成虚构的历史领入单或分发单。
- 历史实际领用日期知道就填，不知道留空；建账日期不能代替历史领用日期。
- 有历史签字凭证可上传，无凭证标注“历史凭证未提供”；不默认将其计入上线后待回传签字单。
- 每件设备只建一条当前记录。旧编号重复先核对，确认同一设备时不重复建账。
- 建账后按普通分发、转交、退回流程操作，现状与后续历史连续可查。
- 建议可以边录边核对，无需一次性录齐全部设备；台账标明首次清点尚未完成时，当前数量只代表已登记数量。

### 新发生的流转

1. 选类型，填日期和交接双方。
2. 添加设备；分发只选在库可用设备，转交和退回选交出方实际持有的设备。
3. 填用途、期限、位置或退回原因；领入和退回时逐件确认正常或故障。
4. 保存草稿或核对后确认。确认前展示设备数量、双方和将发生的状态变化。
5. 确认成功后显示单号，并提供打印与上传入口。

草稿不占用设备。确认时再次核对设备状态；若其他经办人已办理，指出冲突设备，整张单不做部分静默提交。重复点击确认返回同一结果，不生成重复单号。

批量退回允许选择原单的部分设备。正常退回变为在库可用；故障退回变为在库故障；退往上游后仍可查询历史，但不能直接再分发。

## 单据模板

建议编号前缀：领入 LR、分发 FF、转交 ZJ、退回 TH；格式为“前缀-日期-流水”，正式确认时生成，不承诺连续无空号。规则尚待用户审阅。

所有单据采用同一 A4 模板骨架：

| 区域 | 内容 |
| --- | --- |
| 页眉 | 可设置单位名称、单据标题、单号、页码、单据二维码 |
| 交接信息 | 日期、交出方、接收方、团体负责人、用途或原因 |
| 明细表 | 序号、内部设备编号、原资产编号（如有）、设备名称、品牌型号、数量、状况与备注 |
| 汇总 | 合计件数；临时使用的预计归还日期 |
| 签字 | 移交人、接收人、各自签字日期 |
| 页脚 | 补充备注；打印时间可选，不改变交接日期 |

逐件明细数量通常为 1。长明细自动分页并重复表头和单号；签字区与汇总避免被截断。重打已确认单据使用确认时快照，草稿打印带“草稿”标记，作废单打印显著标记作废。浏览器打印提供另存 PDF。

二维码只携带不含人员资料的单据标识，扫码后仍需登录并校验权限。外部领入单可手动关联内部领入记录，不能强求它具有系统二维码。

## 上传与核对

- 可从单据详情直接上传，也可统一上传后匹配候选单据。
- 接受图片和 PDF，支持多页；展示原件预览、匹配单号、交接双方和设备数量。
- 自动识别不自动归档；经办人检查签字及页数是否完整后确认。
- 无法识别时手动选择；多个单号时要求选择，不猜测。
- 误关联的更正保留记录，已归档附件不静默覆盖；重复文件提示已有记录。
- 上传失败允许重试，不改变设备去向；识别失败仍保留成功上传的附件。

## 后续验收场景（计划，未执行）

- 领入 10 个无出厂序列号的电插板，得到 10 个可追踪编号。
- 团体领用需要负责人，允许暂不填具体使用人。
- 借调人员领用后延期，再归还其中一台，剩余设备仍显示在其名下。
- 同一设备并发分发时只能一张单成功，失败方收到明确提示。
- 故障设备直接退往上游，不产生虚假的经办人入库记录。
- 多页单据重复打印单号不变，签字件匹配失败仍可人工归档。
- 待审核账号及停用账号不能读取台账或附件；查询人不能通过 API 修改数据。
- 数据库和附件从同一恢复点恢复后，单据能找到完整原件。
