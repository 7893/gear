# 第一版范围与验收

状态：依据已确认需求整理的验收计划。尚无应用代码，以下场景均未执行；本文不代表验收通过。

## 第一版范围

- 管理几十件、预计不到一百件设备，约十名系统用户，接收对象包括个人和团队。
- 设备分类包含打印机、饮水机、台式电脑、笔记本电脑、电插板、碎纸机、智慧屏及其他；暂不管理耗材。
- 三个业务入口：设备台账、流转办理、单据记录；账号与单位名称放管理设置。
- 支持已有设备建账、新领入、分发、转交、正常或故障退回、临时使用及延期、负责人交接。
- 记录故障、恢复正常、遗失和报废结果；保留历史，不做独立维修工单或报废审批模块。
- 单据编号、A4 打印、签字件上传、编号识别和人工归档形成凭证闭环。
- 按个人或团队导出持有清单进行简单核对；配件随设备备注和明细记录。
- 账号密码登录、开放注册并经管理员审核，管理员、经办人和查询人三种角色。
- 技术和部署分工见[技术选型与部署记录](technical-proposal.md)；本清单不授权创建资源、购买服务或部署，已有基础设施检查不代表应用验收完成。

## 验收场景

| 编号 | 场景 | 应观察到的结果 |
| --- | --- | --- |
| A01 | 登记在库、个人持有、团队持有三类旧设备 | 当前持有情况正确；团队负责人必填；未虚构历史领入和分发单 |
| A02 | 录入不同格式旧编号及无编号设备 | 旧编号及前导零保留；内部编号唯一；重复旧编号提示核对，不覆盖或自动合并 |
| A03 | 批量领入并分发给个人和团队 | 设备逐件可追踪；不同接收对象分别开单；打印与台账明细一致 |
| A04 | 临时人员领用两件设备，延期后只归还一件 | 已归还设备恢复正确库存状态；另一件仍在名下，按新日期提醒 |
| A05 | 个人直接转交团队，随后团队更换负责人 | 不产生虚假入库；新持有方或负责人正确；历史单据快照保持原样 |
| A06 | 使用中的设备登记故障，再退回经办人或直接退上游 | 登记故障不改变持有方；退回才改变去向；故障设备不能正常分发 |
| A07 | 管理员登记遗失或报废结果 | 原因、日期、操作人及历史可查；设备不再作为可分发库存，原领用记录仍可追溯 |
| A08 | 打印含长编号及多页明细的单据 | 编号不截断；每页单号、页码清楚；签字区完整；重复打印单号一致 |
| A09 | 上传图片或多页 PDF，分别模拟正确匹配、识别失败和误关联 | 原件保留；人工核对后归档；失败可手动关联；更正留痕，设备去向不受影响 |
| A10 | 两人同时分发同一设备，或同一人重复点击确认 | 只生成一次有效流转；冲突明确提示；不出现重复持有或部分静默提交 |
| A11 | 修改草稿、作废误单、尝试撤销已有后续流转的单据 | 草稿可改；正式单据由管理员处理并留痕；后续历史不能被简单撤销破坏 |
| A12 | 待审核、停用、查询人分别尝试访问及修改 | 前两者不能获取业务数据或附件；查询人不可写；不能靠直接调用接口绕过限制 |
| A13 | 按团队导出持有清单，再导出单据与附件关联清单 | 清单和当前台账一致；原件能经授权获取；历史编号和关联关系不丢失 |
| A14 | 模拟上传、识别、邮件失败；手动导出启用后也验证导出失败 | 页面或管理员可发现失败并重试；表单内容保留；重试不重复流转或无意义重复通知 |
| A15 | 手动导出与恢复启用后，从归档包恢复数据和附件 | 台账、单据、账号权限和附件对应正确；历史邮件不会自动重发；短期允许暂不启用，不要求每日备份或 30 天恢复点 |
| A16 | 用大陆实际网络完成注册登录、查询、拍照上传、下载及邮件回调 | 所有关键步骤可用，无必须依赖不可达外部资源的阻断；前端为境外托管、自有域名 |

## 需要在实施前细化的参数

- 图片/PDF 单文件大小、单据附件数量、页数上限与允许格式；依据拍照样本和打印页数提出，当前未定值。
- 常用查询响应时间与上传等待提示的验收指标；以设备总量不到一百件为规模，不能未经测量承诺性能。
- 实际使用地区、运营商和浏览器组成的最小访问验证清单；尚未有大陆连通性实测。
- 遗失、报废、找回及更正权限按[统一业务规则](business-rules.md)执行；管理状态和当前持有关系分开，退出管理不等于正常归还。
- 非功能验收需给出实际结果、失败项和证据；文档检查或局部测试通过不代表完整验收。

## 补充规则验收（未执行）

- A17：遗失后找回沿用编号，核对当前持有方和状况；不自动恢复旧期限或伪造归还。
- A18：同团队负责人交接可包含故障设备，状况不被改为正常，旧单负责人不变。
- A19：六类互斥管理统计合计等于有效台账总数，故障交叉统计不重复计入。
- A20：修改权限、退出状态或已有后续事件后，旧会话和早期单据操作不能绕过规则。
- A21（手动导出启用后执行）：清理导出包不会删除业务历史或仍需留存的原始附件。
- A22：完成注册、审核和归还提醒通知，模拟限流、授权失效、发送结果不明及业务状态变化；收件对象正确，过期任务可取消，邮件失败不改变交接或审核事实，未取得收件证据时不显示“已送达”。独立发信验证不代替本场景验收。
- A23：验证邮箱前后均不能绕过管理员审核；管理员批准后只获得所分配角色，重复点击不重复批准或通知。
- A24：验证和重置凭证过期、重复使用、被新请求替代或仅被邮件扫描器打开时，不能错误修改密码；停用账号不能靠密码重置恢复业务权限，重置成功后旧会话失效。
- A25：公开首个注册者不能成为管理员；初始化仅针对部署者指定身份，重复执行不重置已有管理员或提升其他账号；并发降级或停用不能移除最后一个可用管理员。
- A26：在 UTC 与东八区跨日时确认单据、查询到期及生成每日汇总，业务日期按东八区正确计算；预计归还日期不会因时区偏移一天，同一业务日内多次流转顺序明确，服务器和浏览器时区变化不影响结果。
- A27（数据模型提案确认后执行）：存量已分发设备可在未知起始日期时建账，不伪造交接单；一单多设备和部分退回后，各设备当前有效分配唯一，历史快照和签字原件保持可追溯。
