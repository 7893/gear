# 存量建账与台账接入

状态：迁移 005 已获授权应用云端，页面通过既有 CI/CD 发布，独立台账开关已开启；真实设备建账待本人验收。当前部署与其他模块的进度统一见[实现状态](implementation-status.md)。

## 本轮行为

登记已有设备时记录当前情况：经办人库存、个人持有或团队持有。分类包括打印机、饮水机、台式电脑、笔记本、电插板、碎纸机、智慧屏及其他。设备名称、分类及实际状况必填，品牌、型号、序列号、位置和备注可留空。

旧编号保持文本原样，保留前导零；没有旧编号可以直接登记。相同旧编号先提示核对，明确确认是不同实物后才允许各自建立台账，不合并、不覆盖。内部编号由数据库生成，不允许客户端指定，永久唯一。格式已随本次上线确认采用 `SB-000001`，至少六位，超过后自然扩展。

人员和团队是轻量接收对象，不要求其注册账号。人员类型支持本单位、借调、挂职、临时及其他；团队须先选择一个有效个人作为默认负责人。登记设备时再次明确该台设备的责任人，默认负责人只作填表参考。

个人持有时负责人为本人；团队须选有效个人负责人。长期使用不登记归还期限，临时使用必须有预计归还日期。已逾期的存量临时使用可以按真实日期记录，不能因为逾期自动改为库存。跟进经办人记录本次实际建账账号。

库存可填已知到手日期，已发出设备可填已知领用起始日期；未知均保留空值，不用当天日期补造。已知历史日期不能晚于东八区业务当天，临时期限不能早于已知起始日期。日期为纯日期，系统记录时间为 UTC；页面时间点按东八区显示。

建账在单个事务中建立设备、初始事件及必要的使用分配，不创建领入或分发单。初始事件保存当时名称、持有方、负责人和实际日期快照，后续名册变化不能改写它；团队默认负责人变化也不能自动改动已有设备的责任人。历史凭证尚未上传的事实记录在建账事件中，本轮不提供附件上传。

## 接口和权限

[迁移 005](../database/migrations/202610180005_inventory.sql)仅增加设备簿函数，不改共享 Auth、其他应用表或既有数据，不增加业务表，也不开放直接写表或取号权限。

| 接口 | 用途 |
| --- | --- |
| `gear.list_parties()` | 读取当前有效的个人与团队名单 |
| `gear.create_party(details, request_id)` | 管理员或经办人创建接收对象并登记审计 |
| `gear.initialize_asset(details, placement, request_id, allow_legacy_duplicate)` | 管理员或经办人原子登记存量设备及初始分配 |
| `gear.list_assets(search, category, state, holder_kind)` | 读取有效台账、筛选结果及全局六类互斥统计 |
| `gear.get_asset(asset_id)` | 读取设备现状及该设备的审计历史 |

公开接口通过已固定空 `search_path` 的内部实现核对当前验证状态、成员状态和角色。只有启用且邮箱已验证的三种角色可以读取；管理员和经办人可建账及新增接收对象，查询人不能写入。匿名及 `service_role` 不新增执行权。

写入先取得既有设置单行锁，再核对真实身份和权限，与账号变更采用一致锁顺序。操作者来自认证身份，不信任表单中的操作者或角色。必填字段、类型、长度、分类、期限和接收关系都由后端校验，前端校验仅用于及时提示。

两种创建接口使用事件表的唯一请求标识去重；同一账号、同一请求与相同内容重试返回最初结果，换内容或操作者则报冲突。权限检查在去重返回之前，停用账号不能重放旧请求读取结果。客户端在当前表单内为相同内容复用请求标识，提交失败保留填写内容，不在网络异常后自动新建请求。刷新后不承诺恢复表单或请求标识，页面提示先核对台账。

## 页面

运行配置 `inventoryEnabled` 由 `GEAR_INVENTORY_ENABLED` 控制，只有字面 `true` 才开放，缺省关闭。本次已在迁移与权限核对通过后开启。有权账号首页进入台账，未审核或停用账号继续查看自己的账号状态；`/#/account` 保留账号入口。

| 路由 | 功能 |
| --- | --- |
| `/#/assets` | 台账、编号/名称/型号/持有方/位置搜索、分类/状态/持有情况筛选 |
| `/#/assets/new` | 登记已有设备，表单内另有新增个人或团队的轻量入口 |
| `/#/assets/:id` | 设备当前情况、负责人、期限及初始历史记录 |

台账显示六类互斥数量，在管故障作为交叉统计单列，不重复计入总数；统计针对全部有效设备，筛选结果数量另列。查询失败显示重试，不当成零台。搜索按普通文字匹配，不把 `%`、`_` 或输入内容当查询表达式。长旧编号完整保留，窄屏允许横向查看表格。

页面按当前权限显隐，异步返回需匹配当前查询和权限；失权或离开后不能让旧响应重新填回设备数据。数据库权限始终是最终边界。

## 检查与上线边界

[隔离数据库检查](../database/tests/check_inventory.py)覆盖角色、直接写入拒绝、并发重复请求、编号唯一和位数扩展、旧编号确认、三类持有关系、未知日期、日期校验、临时期限、故障现状、统计和名册失效。浏览器检查使用虚构 API，覆盖发布开关、查询人、建账、重复旧编号、响应丢失重试、团队负责人及失权后的迟到响应；不代表已在真实数据库登记设备。

本轮已获授权应用迁移、确认内部编号格式、发布页面及开启仓库变量。迁移前后核对确认共享配置、既有结构、业务数据和编号序列保持不变；以有效管理员角色在只读事务中验证台账与接收对象查询。检查没有创建真实或测试接收对象、设备、使用分配及交接单，也没有消耗编号；后续由本人登记并核对真实设备。现有网站 CD 不会自动执行数据库迁移。

回退入口时关闭 `GEAR_INVENTORY_ENABLED` 并重新发布；数据库、已生成编号和审计历史继续保留，不通过删除 schema 或业务记录回退。真实部署参数、迁移基线和发布检查原文仅放在忽略的私有记录中。

新领入、分发、转交、退回、延期、故障处置、资料编辑、名册编辑或停用、附件上传、打印、识别、归档、导出及到期邮件不属于本轮实现，不用建账接口模拟这些操作。
