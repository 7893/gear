# 邮件模板与操作规则

设备簿采用统一的中文纯文本邮件，标题为 `【设备簿】通知事项`。正文直接说明本次用途、必要内容与下一步操作，不为当前规模增加邮件编辑器或模板后台。

可复用的模板代码位于 [templates.ts](../supabase/functions/gear-auth-mail/templates.ts)。模板负责生成标题和正文，不负责验证验证码、授予权限、修改密码、选择收件人或提交邮件。

## 模板清单

| 模板 | 收件人及必要内容 | 用户操作与结果 |
| --- | --- | --- |
| 注册邮箱验证 | 注册邮箱；六位纯数字验证码 | 回到验证页输入验证码；验证成功后进入待审核，不直接获得设备权限 |
| 找回登录密码 | 请求账号邮箱；本次找回用途的六位验证码 | 在找回页验证后设置新密码；收信本身不修改密码，不批准或恢复设备簿权限 |
| 确认本人操作 | 当前账号邮箱；本次敏感操作验证码 | 回到对应页面完成验证，不把它当成注册或找回密码凭证 |
| 新使用申请 | 当前有效管理员；已验证申请人的姓名 | 登录账号管理审核，邮件不能直接批准 |
| 使用申请通过 | 申请人；处理结果及角色名称 | 使用注册邮箱和原密码登录 |
| 使用申请未通过 | 申请人；处理结果 | 登录查看处理说明，确需重新申请时联系管理员 |
| 登录密码已更改 | 对应账号邮箱；密码变更通知 | 非本人操作时通过正常找回流程保护账号并联系管理员 |
| 设备簿权限停用或恢复 | 账号持有人；当前状态，恢复时列当前角色 | 登录查看状态；停用不代表已领设备已经归还 |
| 临时使用到期汇总 | 当前经办人，不可用时转给管理员；业务日期及即将到期、今日到期、逾期件数 | 登录查看具体设备并归还或延期，邮件不附整本台账 |

## 验证码规则

- 注册流程为：填写姓名、邮箱和密码 → 发送验证码 → 输入六位数字 → 服务端验证 → 待管理员审核。服务器可先保存未验证的认证身份，但其不能访问设备数据，不能进入可批准的业务成员状态。
- 注册与找回验证码都通过成熟认证服务生成、校验、过期及限制使用次数，不由邮件模板生成，也不能把八位码截取为六位码。
- 六位码按字符串处理，保留开头的零；只接受 `0` 至 `9`，不接受字母、全角数字或其他长度。认证邮件不放验证链接，也不把验证码写进标题、普通日志或业务待发表。
- 找回时必须校验邮箱、验证码和用途，再允许设置新密码。密码不出现在邮件中，找回不改变账号审核状态或角色。
- 未登录请求保持统一提示，不通过邮件接口公开账号是否存在。发送失败不声称已送达，重发继续限流。
- 当前认证服务验证码有效期为一小时，邮件不另行承诺不同期限；调整期限须另行核对共享影响。验证码长度的服务端配置与前端、模板必须一致。

## 通知规则

普通通知可以包含从私有配置取得的系统入口，登录后仍要校验当前权限；这类链接与注册、找回验证码不同。邮件不含免登录审批、直接停用或直接修改密码的按钮。

通知发送前重新查询当前收件人、成员状态和业务事件，取消过时任务。提醒按业务东八区计算日期并按人汇总，内部时间点保存 UTC。系统内没有符合条件的提醒时不发空汇总。

模板不读取真实配置或凭据。邮件中的入口由服务器从私有运行配置传入，仅接受无用户信息、查询参数或额外路径的 HTTPS origin，再生成固定系统路由。真实邮箱、地址、验证码和正文不进入公开仓库。

## 实现状态

注册页面及六位码模板已完成本地实现和验证，共享验证码长度已获授权由八位改为六位，邮件函数已更新，页面按既有 CI/CD 发布。认证 Hook 目前服务整个 Supabase 项目；设备簿注册模板根据已有注册标记选择，其他应用的通用邮件保持原行为。该标记只选文字，不能用于授权。

找回密码、确认本人操作和普通通知的模板已准备；找回页面、凭证验证后的改密及会话处理、业务待发消费和定时汇总尚未接入。不能把模板存在等同于这些流程已经完成。未来接入找回时须明确识别设备簿请求来源，不能只看共享用户是否曾注册设备簿就改写其他应用的找回邮件。

停用、恢复与密码变更模板不代表已经新增对应通知任务或启用项目安全通知；当前数据库只登记申请待审核、审核结果和到期汇总三种待发类型，业务发送开关保持关闭。完整接入后再验收实际收发、错误码、过期码、重复使用、限流及权限隔离。
