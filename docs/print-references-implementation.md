# 横向打印、可读编码与扫码核对

2026-10-20 用户要求统一默认 A4 横向、改善 UUID 与旧设备编码的可读性，并让普通扫码能打开相应信息。

## 打印与二维码

公共打印样式默认 `A4 landscape`，保留重复表头、页码、签字栏、长编号换行和原单快照。页面提示横向与关闭浏览器自带页眉页脚。打印机或浏览器仍允许使用者手动覆盖纸张设置，本轮验证以浏览器生成的 PDF 尺寸为准，实体打印继续暂缓。

共用 `RecordQr` 生成带留白区的黑白 SVG，纸面二维码约 25 mm。正式单据使用当前站点的核对链接与正式单号；设备详情也提供核对二维码。实际域名在浏览器运行时确定，不写入源码或公开文档。

扫码先进入适合手机的核对页：未登录仅显示类型和二维码中已有的编号，不查询台账；登录后自动回到原记录，显示当前状态、交接双方或持有方、日期，以及完整记录入口。作废单据及无效设备明确提示。所有读取仍检查当前成员权限，二维码不包含登录凭据、人员资料或签字确认结论。登录返回地址仅允许本应用的核对路径，拒绝外部跳转。

上传识别继续识别链接中的正式单号，复用原匹配、上传与人工核对管道；旧 `gear:document:UUID` 二维码仍可用于上传匹配。旧纸张中的纯文本二维码本身无法变成网址，需要重新打印才能由普通扫码软件直接打开。

## 可读业务编码

共用编码格式为类型、东八区创建年份和八位分组 Crockford Base32 字母数字，例如 `EQ-26-7K4M-9P2X`。字母表不使用 I、L、O、U。设备 EQ、单据引用 DC、个人 PE、团队 TM、其他对象 PT、附件 AT。正式交接单号继续使用既有类型、日期及业务日流水，草稿和附件使用新引用编码，不再把 UUID 当作主要展示标识。

迁移 023 在设备、单据、对象和附件表追加生成列及唯一索引；统一冻结保护只忽略不可直接修改的派生编码列，原件、原单源字段仍完整冻结；原 UUID、旧内部设备序号、分配、事件、原单快照和取号流水保持。若出现短码冲突，唯一约束拒绝产生歧义，不静默覆盖或关联错误对象。编码用于阅读和定位，不是访问凭据。

资产公共读取集中返回 EQ 显示码和历史内部编号别名；台账支持新旧编号搜索。统一引用解析 RPC 受认证权限保护，并继续限制非本人草稿；旧 UUID 链接兼容。对象编码、单据编码与附件编码用于对应清单、CSV 和原件下载目录，内部业务调用及校验清单保留 UUID 关联。

批量导入的持有方、负责人和使用人列改用编码，预览按当前对象对照表转换为内部 ID 再提交，不按姓名猜配。旧版 ID 表头和 UUID 内容继续支持；同名人员通过编码区分。
