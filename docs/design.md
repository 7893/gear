# 设计草案

本文是讨论起点，不代表技术选型或最终规格。

## 页面

尽量保留三个主入口：

| 入口 | 内容 |
| --- | --- |
| 设备台账 | 搜索、状态筛选、当前持有情况、设备详情和流转历史 |
| 流转办理 | 领入、分发、转交、退回，支持多设备一次办理 |
| 单据记录 | 查询编号、打印、上传签字件、核对归档、待回传列表 |

统计和到期提示可放在台账顶部，人员、团体与位置采用轻量选项维护，不必各做复杂模块。

## 最小数据

| 对象 | 建议记录 |
| --- | --- |
| 设备 | 唯一编号、名称、分类、品牌型号、序列号（如有）、来源批次、当前位置 |
| 接收对象 | 个人或团体、姓名或名称、所属单位、接收负责人、人员类型 |
| 流转单 | 内部编号、类型、交接日期、交出方、接收方、设备明细、备注 |
| 使用分配 | 设备、使用人或团体、开始日期、预计归还日期、实际结束日期 |
| 签字附件 | 所属单据、原始文件、上传时间、识别结果、核对结果 |

设备编号标识一件设备，单据编号标识一次交接；一张单据可包含多件设备，一件设备可关联多张历史单据。

## 状态建议

为避免把“在哪里”和“是否损坏”混为一谈，底层区分：

- 持有情况：经办人在库、已分配、已退往上游。
- 设备状况：正常、故障；其他情况待业务确认后补充。
- 单据有效性：草稿、已确认、已作废。
- 凭证归档：待回传、待核对、已归档。

界面可以组合显示“在库可用”“使用中”“在库故障”等易懂标签。设备转交不清除历史，人员离开也不删除其领用记录。

## 单据与打印

- 建议正式确认时生成唯一单号，格式示例：`LR-20261016-001`，最终前缀与流水规则待定。
- 重打保持原编号，作废编号不再使用。
- 建议 A4 打印，含标题、编号、日期、交接双方、设备清单、备注、签字栏。
- 多页显示同一单号和页码，可通过浏览器保存 PDF。
- 确认后的交接信息不能任意覆盖；录错通过作废或更正留痕。
- 存在后续流转时，不能简单撤销早期单据导致当前台账失真。

## 一致性与识别

- 同一设备同一时刻只有一个有效持有关系。
- 提交确认应同时记录流转与更新台账，重复点击不能重复开单。
- 故障设备未经处理确认不能作为正常可用设备再次分配。
- 归还期限变化不等于设备交接，实际归还需明确登记。
- 识别优先解决“这张纸属于哪张单”，不默认承诺准确转写手写姓名或验证签名真伪。
- 上传附件本身不修改设备去向，归档由经办人核对确认。

## 运维边界

已确定互联网使用、约十名系统用户、允许云服务、电脑操作为主，以及源码公开开源。尚未选择框架、数据库、OCR 服务或托管平台；当前只做设计，不部署服务，也不创建远程仓库。

### 针对已确认边界的设计建议

- 采用登录后访问的应用，数据库和签字附件不因源码公开而开放匿名访问。
- 使用独立账号记录操作人；管理员、经办人、查询人三种角色及全台账可见范围已确认，详见需求文档。采用账号密码登录，开放注册但须管理员审核。
- 多人同时办理时检查设备当前持有关系，避免同一设备被重复分配；单号生成需保证并发下唯一。
- 优先优化电脑端表格、批量操作和打印；手机支持查询与拍照上传已确认。
- 仓库仅保留源码、文档和虚构示例数据，不纳入实际台账、签字附件、数据库备份或服务凭据。
- 每日自动备份数据库和附件，保留 30 天；接受最多一天的数据损失窗口。建议保留独立副本，并在正式使用前明确恢复步骤和验证方式。
- 开源许可证与远程仓库位置待定，后续单独办理发布。

## 注册审核与邮件（流程建议）

- 账号状态分为待审核、已启用、已拒绝、已停用；待审核用户只能查看审核状态，不能查询台账或附件。
- 申请人不能自行授予角色；管理员审批时分配角色，建议默认查询人。
- 建议注册提交后通知管理员，审批通过或拒绝后通知申请人；到期提醒等业务邮件范围另行确认。
- 邮箱验证、密码重置邮件和首次管理员初始化方式在安全设计阶段细化。
- 管理员重置密码应使用一次性重置流程，不查看或发送用户原密码。
- 邮件发送失败应可追踪和重试，不回滚已经完成的审核或流转操作。

## 选型约束

- 优先评估具有免费额度的互联网托管、数据库、附件存储、邮件和识别产品，允许必要的小额付费。
- 免费额度、产品限制和价格在正式选型时查证，不将当前草案视为零费用承诺。
- 同时考虑约十名用户、签字附件增长、30 天备份保留和邮件发送的用量。
- 具体付费上限、平台和开源许可证尚未确定；当前不创建云资源或订购服务。
