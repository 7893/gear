# 设计草案

本文是讨论起点，不代表技术选型或最终规格。

## 页面

尽量保留三个主入口：

| 入口 | 内容 |
| --- | --- |
| 设备台账 | 搜索、状态筛选、当前持有情况、设备详情和流转历史 |
| 流转办理 | 领入、分发、转交、退回，支持多设备一次办理 |
| 单据记录 | 查询编号、打印、上传签字件、核对归档、待回传列表 |

统计和到期提示可放在台账顶部，人员、团体与位置采用轻量选项维护，不必各做复杂模块。

## 最小数据

| 对象 | 建议记录 |
| --- | --- |
| 设备 | 唯一编号、名称、分类、品牌型号、序列号（如有）、来源批次、当前位置 |
| 接收对象 | 个人或团体、姓名或名称、所属单位、接收负责人、人员类型 |
| 流转单 | 内部编号、类型、交接日期、交出方、接收方、设备明细、备注 |
| 使用分配 | 设备、使用人或团体、开始日期、预计归还日期、实际结束日期 |
| 签字附件 | 所属单据、原始文件、上传时间、识别结果、核对结果 |

设备编号标识一件设备，单据编号标识一次交接；一张单据可包含多件设备，一件设备可关联多张历史单据。

## 状态建议

为避免把“在哪里”和“是否损坏”混为一谈，底层区分：

- 持有情况：经办人在库、已分配、已退往上游。
- 设备状况：正常、故障；其他情况待业务确认后补充。
- 单据有效性：草稿、已确认、已作废。
- 凭证归档：待回传、待核对、已归档。

界面可以组合显示“在库可用”“使用中”“在库故障”等易懂标签。设备转交不清除历史，人员离开也不删除其领用记录。

## 单据与打印

- 建议正式确认时生成唯一单号，格式示例：`LR-20261016-001`，最终前缀与流水规则待定。
- 重打保持原编号，作废编号不再使用。
- 建议 A4 打印，含标题、编号、日期、交接双方、设备清单、备注、签字栏。
- 多页显示同一单号和页码，可通过浏览器保存 PDF。
- 确认后的交接信息不能任意覆盖；录错通过作废或更正留痕。
- 存在后续流转时，不能简单撤销早期单据导致当前台账失真。

## 一致性与识别

- 同一设备同一时刻只有一个有效持有关系。
- 提交确认应同时记录流转与更新台账，重复点击不能重复开单。
- 故障设备未经处理确认不能作为正常可用设备再次分配。
- 归还期限变化不等于设备交接，实际归还需明确登记。
- 识别优先解决“这张纸属于哪张单”，不默认承诺准确转写手写姓名或验证签名真伪。
- 上传附件本身不修改设备去向，归档由经办人核对确认。

## 运维边界

正式使用前确定访问方式、数据库与附件存储、备份和恢复方式。尚未选择框架、数据库、OCR 服务或托管平台，不部署任何服务。
