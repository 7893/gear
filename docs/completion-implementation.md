## 历史建账和事件凭证

设备详情中的建账、故障、维修、遗失、报废、找回、误建作废和处置撤销记录提供“查看或补传凭证”。历史单据直接关联建账事件，不生成新的正式交接单，不补造日期或签字。原建账快照保持，当前附件状态独立读取。

复用现有私有桶、身份校验、文件校验、上传重试、下载服务和附件表。`document_id` 与 `event_id` 继续互斥，上传服务只接受一个目标。单文件 PDF/JPEG/PNG，最多 20 MiB；PDF 最多 20 页，图片一页；每个事件最多 10 份待完成或已完成的有效原件，合计 100 MiB。文件名、大小、类型、哈希、版本、重复文件和当前成员权限由服务端校验。

管理员和经办员可补传，浏览者只能读取已完成原件。待完成文件仅管理员或上传经办员可见，可取消后重传。上传后需下载查看，填写核对说明，明确确认相符或标记不采用；已核对材料只有管理员能改判。被否定的原件和核对历史保留，不移动原件、不冒充新交接。此入口不自动识别历史签字或凭证语义，现有正式单据的二维码/单号识别及人工归档流程保持。

新增 `list_event_evidence`、`reserve_event_attachment`、`review_event_attachment`，扩展原有下载与字节完成接口。附件操作不改变设备状态或持有关系。事件目标限定为上述类别，不能把附件挂到任意成员、设置或草稿事件。

## 异常处置纠错

管理员在设备详情中填写原因，明确撤销最近未撤销的遗失、报废、找回或误建作废。`correct_asset_lifecycle` 锁定版本并核对当前状态、原事件及后续依赖；已有后续有效状态事件时拒绝，不自动级联撤销。

追加 `asset_lifecycle_corrected` 及 `reverses_event_id`，原事件不能改写或删除。恢复原状态及原分配的身份、负责人、使用人和期限；撤销错误找回时关闭该次新分配。保持内部编号、单据、附件和独立资料更正。真实找回继续使用原“登记找回”，按实际持有关系重新分配；纠错仅用于撤销错误登记。

## 到期节点邮件

单位设置可保存开关、提前天数（0—30 天）、发送时间（东八区）和原因。最新频率为提前一次、当天一次，逾期第 3 天起每隔 3 天；同一天不同设备合并。只统计本次到达节点的设备，完整到期清单保持持续可查。数据库时间仍为 UTC，业务日使用东八区。新开关默认关闭；不会开启全局通知开关或新建调度、密钥和云服务。

复用已存在的每日到期中文模板、通知队列、Cron 唤起和 Gmail 发送器。邮件只包含即将到期、今日到期、逾期的数量和系统入口，明细进入登录后的到期清单查看。每位有效跟进经办人每业务日最多一封；经办人停用、身份缺失或邮箱未验证时汇总给有效管理员。个人设备接收者不必有系统账号，不直接向任意表单邮箱发信。

入队和发送前都按当前分配重算，排除已归还、退出管理、无效及不再临近的设备。重复触发不重复排队，不补历史日期；取消、已提交或结果不明的同人同日任务不自动重新发送。保留全局每日最多 50 次尝试、租约、有限重试和结果不明不盲重发的保护。管理员可在现有通知状态中查看每日汇总类型。修改发送时间或重新启用不重发当天已处理任务。

## 已有设备批量导入

设备台账提供批量导入。先下载空白模板及当前人员/团队 ID 对照表，表格软件另存为 **CSV UTF-8**，选择文件后预览，勾选确认才提交。使用 PapaParse 解析引号、逗号、多行中文文本；不自动转换数字，原编号前导零保留。首版不直接解析 `.xlsx`。

每行一台，最多 200 行、文件 1 MiB。分类和状况使用模板说明中的中文或代码；日期为 `YYYY-MM-DD`，未知起始日期留空。库存设备不填持有关系；个人持有者与负责人相同；团队必须指定个人负责人，实际使用人可选。按对象 ID 区分同名，不能凭姓名猜配。

预览检查表头、列数、字段长度、日期及接收关系，列表共用分页。提交在一个事务中复用 `initialize_asset` 和具体使用人接口，重新校验当前权限、名单和重复编号；失败明确指出 CSV 逻辑记录行，整批无新增设备和事件。多行单元格按一条逻辑记录计数，不等于物理文本行。重复旧编号需单独勾选，仍生成不同内部编号。只新增，不更新或自动合并现有台账。事务回滚允许编号出现空号，不回收编号。

整批请求和每行都有稳定请求标识，响应丢失可用同一请求重试，已成功的批次返回原结果；不同内容不能复用请求。导入成功后仍需到设备详情补历史凭证。替换演示数据需要另行核对和授权，不包含在导入中。

## 原件批量下载

单据列表提供“批量下载全部凭证原件”，范围明确为全部有权读取且已完成的原件，包括事件历史凭证、作废单据及不采用的原件，不受单据列表筛选影响。复用原下载身份校验；私有路径、访问令牌和公开下载 URL 不写入 ZIP 清单。

使用 fflate 生成 ZIP，包含按附件 ID 分目录的原文件，以及关联、状态、大小和 SHA-256 清单。下载逐件核对大小及哈希，完成前再比对关联清单；任一失败、权限变化或关联变化都不生成缺件包。支持最多 1000 份、合计 25 MiB，超出时使用下述手动整体备份。该上限保持页面轻量，不另建后台打包服务。共用 `DownloadAction`、下载工具和 `useAuthorizedAction`，CSV 也复用相同的退出、旧响应丢弃与取消规则。

## 手动整体备份和恢复

使用 [backup.py](../scripts/backup.py)，无新 Python 依赖，调用 PostgreSQL 自带 `pg_dump`、`pg_restore`、`psql`。不安装定时备份，不创建付费产品或对象存储副本。按需手动运行；是否再复制到私有云存储由维护者决定。

导出内容：网站构建交付文件、项目公开及私有两个应用模式（表、序列、函数和权限），以及全部已完成原件。数据库使用同一个只读一致性快照，原件依据该快照取出并校验。包含未采用、非有效的已完成原件；不把待完成上传或孤立文件冒充已归档原件。包内清单记录每个文件的大小与 SHA-256。上限 2 GiB / 10000 文件。

共享 Supabase Auth 的账号密码、其他应用、Vault 密钥、Cron 安装及云配置不在备份内。恢复需要已有原 Auth 用户 ID 和 Supabase 角色；应用账号权限及身份关联按原样恢复。适用于原项目应用模式恢复，或已具备这些身份与平台能力的隔离目标；不承诺把认证账号无损迁移到一个全新的 Supabase 项目。跨项目 Auth 迁移需另外设计和授权。

连接使用 libpq 的私有 `PGSERVICE`/服务文件或 `PGHOST`、`PGPORT`、`PGUSER`、`PGDATABASE`、`PGPASSFILE`。凭据不放命令行、公开文档或版本库。可用 `PG_BINDIR` 选择兼容的客户端工具。Storage 使用私有环境中的 `SUPABASE_URL`、`GEAR_STORAGE_BUCKET`、`SUPABASE_SECRET_KEY`；应用模式来自 `GEAR_DB_SCHEMA`，私有模式从同一年份推导。工具不会自动加载 `.env` 或猜生产目标，运行前由维护者在私有进程环境提供。

构建后导出和离线校验的命令结构如下，文件均为本地私有数据：

```sh
python3 scripts/backup.py export --web-root web/dist --output backups/manual.gear-backup.tar.gz
python3 scripts/backup.py verify backups/manual.gear-backup.tar.gz
```

`verify` 只解包校验，无数据库或网络访问。拒绝路径越界、链接、重复成员、额外文件、超限及哈希错误。网站目录必须是构建产物，拒绝隐藏文件、凭据目录及符号链接。包包含真实业务资料和运行时地址，文件权限为 600、临时目录为 700，必须私有留存；压缩不是加密。`.env`、服务端凭据和源码工作目录不打包。

恢复默认仅预检，不写数据库、存储和网站目标；需要目标数据库的只读权限。目标网站目录必须不存在或为空，两个应用模式必须不存在，拒绝覆盖现有业务。预检不通过时不会上传原件。先确认包来源可信，核对 SHA-256 以及私有连接确为隔离目标，再显式传入完整指纹：

```sh
python3 scripts/backup.py restore backups/manual.gear-backup.tar.gz --web-root local/restored-site
python3 scripts/backup.py restore backups/manual.gear-backup.tar.gz --web-root local/restored-site --confirm-sha256 '<verified-sha256>'
```

带指纹的第二条是维护写操作，**不属于本轮线上授权**。备份中的 SQL 必须来自可信维护者；哈希证明完整性，不证明来源。工具从不自动删除旧模式、不清空桶、不更改 Auth、Nginx、DNS、证书或其他项目。

恢复先核对原件：同路径同内容可复用，不同内容拒绝覆盖；新增原件回读校验后，用一个数据库事务恢复并关闭当前模式中已有的邮件开关（兼容迁移 013 与 021）、清理未发送任务的租约，追加恢复记录，历史邮件不会自动重发。网站文件只恢复到本地目标目录，不部署。数据库、Storage 和文件系统无法组成同一事务；失败不自动删对象，可能留下本次新增的孤立原件；根据私有清单核对后重试，不能把失败当作恢复完成。

本地测试用真实 `pg_dump/pg_restore` 在一次性数据库中往返，Storage 使用真实 HTTP 适配器配合内存传输替身，分别核对迁移 013 与 021 的台账、账号权限、原件、网站字节、禁止覆盖和已有邮件开关关闭。缺失原件兼容 HTTP 400/404 加语义 404 的明确缺键响应；缺桶、无权限、上传失败及不明错误均中止，不误判成可上传空位。没有连接真实数据库或发邮件。生产恢复、真实文件量、客户端工具版本与平台身份权限仍需届时单独验收。
