# 账号与访问流程设计

状态：核心流程已确认：邮箱加密码登录，先验证邮箱再由管理员审核，审核默认查询人，密码通过一次性流程找回，首次管理员由部署者初始化，停用保留历史。已确认共用现有 Supabase 项目，身份和密码共享，设备簿成员、审核与角色独立。具体参数和跨应用影响仍待核定；尚未实现或验收。

## 1. 最小账号信息

以邮箱作为登录账号，另存显示姓名，不再额外维护一套用户名。账号使用不随邮箱或姓名变化的内部标识，历史操作始终关联该标识。

邮箱验证、业务状态和业务角色分别记录：

| 维度 | 值 | 用途 |
| --- | --- | --- |
| 邮箱验证 | 未验证／已验证 | 证明申请人能够接收该邮箱的邮件，不等于获准使用系统 |
| 业务状态 | 待审核／已启用／已拒绝／已停用 | 决定账号能否访问业务 |
| 业务角色 | 管理员／经办人／查询人 | 启用后按固定角色授权；待审核时不授予业务角色 |

只有邮箱已验证、账号已启用且具有有效业务角色时，才能访问台账与附件。注册表单不接受申请人自选管理员或修改角色；设备接收人、团队负责人和登录账号仍是不同对象。

## 2. 注册、验证与审核

已确认流程：填写姓名、邮箱和密码 → 验证邮箱 → 等待管理员审核 → 管理员分配角色并启用 → 使用账号密码登录。

- 注册后仅有受限制的注册/审核状态访问能力，不能读取台账、附件、导出或其他申请人的资料。
- 先完成邮箱验证，再进入可批准的审核队列并通知管理员；邮箱未验证时管理员不能直接批准。
- 验证邮件失败时保留申请，提示稍后重发，不伪报发送成功。重发要限流；新链接生效时旧链接失效，过期链接可重新申请。
- 管理员核对申请人，选择查询人或经办人；默认查询人，新增管理员须明确选择，不能从申请表字段取得角色。
- 审核操作在后端重新核对当前状态，重复点击不会重复启用或重复生成通知；通过或拒绝后记录操作人、时间及结果。
- 已拒绝申请不因重复注册自动回到待审核；确需重新申请，由管理员核对后恢复待审核。已停用账号也不能靠再次注册绕过停用。
- 未登录时，对重复邮箱、找回密码等请求统一响应，避免公开暴露账号是否存在；完成身份验证后可以查看自己的申请状态。

邮箱验证只证明邮箱控制权，是否属于本系统允许使用的同事仍由管理员判断。不增加单位域名白名单、组织架构同步或多级审批。

共用项目时，已有其他应用的 Auth 身份不自动获得设备簿权限。已有账号通过正常登录验证身份后另行申请设备簿成员资格，不覆盖其密码、邮箱或其他应用角色。

## 3. 登录、权限与停用

- 登录后，未完成邮箱验证或审核的申请人停留在自己的状态页。被拒绝或停用的账号不能获得业务数据；验证密码成功也不等于业务授权成功。
- 首页对正常启用账号进入设备台账。退出后清理当前会话；业务接口、附件下载和导出均在服务端检查当前状态与角色。
- 停用或变更角色后，下一次业务请求按新权限处理；不能只隐藏按钮，也不能等旧令牌自然过期后才生效。
- 管理员停用账号不删除历史单据、操作记录或设备接收人资料，不自动归还设备。旧经办人不可用时，提醒按统一规则转给管理员。
- 共用 Supabase 时，停用只更新设备簿成员状态，不封禁或删除共享 Auth 用户，不全局撤销其他应用会话；退出只处理设备簿当前会话和本地状态。
- 恢复停用账号时由管理员核对角色及邮箱验证状态，不自动恢复不再适用的旧权限。
- 第一版不提供自助更换登录邮箱；确需更换时采用受控维护，核对身份并验证新邮箱，保留内部标识、历史归属和变更审计。

## 4. 修改密码与找回密码

- 使用成熟认证能力保存和校验密码，不保存可读原密码，不自行设计加密算法。允许使用密码管理器；具体密码强度参数在认证选型时确定。
- 已登录用户修改密码时重新核对当前身份。修改成功后结束旧会话，并通过正常登录重新进入，不在邮件中发送新旧密码。
- 建议仅对已验证、已启用账号提供自助邮件重置；其他状态由管理员核对申请。密码重置不能自动验证邮箱、批准申请、恢复停用或提升角色。
- 忘记密码请求统一响应，按邮箱、来源和整体发送量限流，避免向任意邮箱无限发信或被外人反复请求导致永久锁定。
- 重置凭证只用于指定账号与用途，有期限、不可猜测且只能使用一次；新请求生效时旧凭证失效。仅打开邮件链接不直接修改密码，需用户主动提交新密码。
- 管理员重置密码是发起同一受控重置流程，不能读取用户密码或自选邮箱接收他人的重置链接。失去邮箱访问能力时走身份核对和受控恢复，不以安全问题或公开链接代替验证。
- 发信失败、链接过期和令牌已使用应有可理解的提示；失败不改变业务状态。重置成功后使旧会话失效，不自动登录。

共用项目时，同一 Auth 身份的密码由各应用共享；修改或找回影响该身份在其他应用中的登录，相关会话处理需按平台能力核对。上线前明确提示这一账号级影响，不能宣称设备簿拥有独立密码或以重置密码替代本应用停用。

## 5. 首次管理员与恢复

首次管理员通过部署者在私有环境执行的一次初始化建立，指定邮箱、完成邮箱控制权验证并由本人设置密码。初始化不提供公开网页入口，不将真实邮箱或初始密码写入源码。

- 不能把第一个公开注册者设为管理员，不能让任意注册账号认领初始化身份。
- 初始化只作用于指定身份；重复执行不能重复创建、覆盖密码或顺便提升其他账号权限。已有管理员时，不再次开放初始化。
- 停用、降级等管理操作必须在并发下保留至少一个已验证、已启用的管理员；第一版不物理删除账号。
- 管理员忘记密码先走正常找回。所有管理员均无法登录或邮件不可用时，由部署者在受控环境执行恢复，记录身份核对和权限变更，不提供永久开放的万能恢复入口。
- 项目管理员是设备簿自己的业务角色，与 Google Workspace 管理员或云项目管理权限无关。应用不需要这些外部管理权限。

## 6. 页面与运行边界

只补充登录、注册、邮箱验证、审核状态和找回密码这些必要页面；管理动作集中到现有管理设置，不新增工作台或审批系统。页面与实际接入以大陆网络完整可用为验收要求。

注册、验证、审核和重置邮件使用[邮件与通知设计](email-design.md)中的通道与失败规则。邮件链接使用应用自身入口；最终认证产品必须支持实际回调及自定义发信方式，不能因单独发信测试成功而认为完整认证已打通。

登录失败采用统一提示并限速，密码、令牌和完整验证/重置链接不得进入普通日志或公开仓库。默认使用 HTTPS；会话、请求防伪和密码存储由选定认证实现提供并验证，不把自行拼装登录作为当前技术结论。

待实施前确定：密码强度参数、验证/重置凭证有效期、登录会话期限和请求限流数值；不在当前设计中虚构已经确认的具体值。

参考：[OWASP 认证建议](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)、[OWASP 密码找回建议](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html)。这些资料为实现安全措施提供依据，本项目的业务取舍仍以已确认规则和明确标注的建议为准。
