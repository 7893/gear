# 日常操作设计

状态：供审阅的轻量业务草案，尚未实现。面向不足一百件设备、约十名系统用户；不增加复杂审批、组织架构、多级仓库或自定义权限。

## 一套交接表单

分发、转交、退回使用同一表单，根据操作显示需要的字段。每张单对应一组交出方和接收方，可包含多件设备；发给不同个人或团队时分别开单，避免一张签字单混淆接收责任。

| 字段 | 分发 | 转交 | 退回 |
| --- | --- | --- | --- |
| 设备 | 从在库可用设备中勾选 | 从当前持有方名下勾选 | 从当前持有方名下勾选，允许只退部分 |
| 交出方 | 自动显示经办人库存 | 自动带出当前个人或团队 | 自动带出当前个人、团队或经办人库存 |
| 接收方 | 个人或团队，必填 | 新个人或团队，必填 | 经办人库存或上游单位，必填 |
| 接收人 | 个人本人或团队负责人 | 同分发 | 实际接收人，必填 |
| 实际交接日期 | 默认今天，可修改 | 同分发 | 同分发 |
| 使用期限 | 长期或临时；临时必填预计归还日期 | 重新确认新期限，不沿用旧使用人期限 | 不填，结束所退设备的当前使用记录 |
| 设备状况 | 自动带出正常 | 自动带出正常；故障设备走退回 | 逐件确认正常或故障，故障填简短说明 |
| 位置、备注 | 选填 | 选填 | 选填 |

系统经办人是操作账号，实际移交人、接收人是交接双方，允许不同。多人经办时“在库”统一表示本单位待分发库存，实际保管人可记录，不为每个账号创建独立仓库。

表单底部只提供“保存草稿”和“确认交接”。确认前展示双方和设备数量；保存草稿不改变台账，确认交接后才改变持有关系并生成正式单号。若日期早于该设备最近一次有效流转，提示不能直接补插历史，交管理员核对，避免改乱当前去向。

确认后提供“打印单据”和“上传签字件”。正式单据允许先确认后打印签字，签字件尚未回传时标记待回传；经办人须在实际交接发生时确认，不用草稿或预计交接代替事实。打印与上传不再触发一次设备流转。

## 日常补充操作

- **延期**：选择当前临时领用记录，填新日期和简短原因，保存变更记录，不生成虚假的交接单。部分设备延期时可只选需要延期的设备。
- **登记故障**：在设备详情记录故障及说明，持有人不变；实际交回时再办退回。故障未处理前不允许分发或正常转交。
- **恢复正常**：经办人记录处理结果和日期后恢复正常，保留记录；不增加完整维修工单模块。
- **上游修好后领回**：选择原设备办理再次领入，沿用内部编号，记录实际状况；换成另一件设备时新建台账，不把新设备覆盖到旧设备记录上。
- **团队负责人变化**：旧单据不改写。若发生责任交接，允许同一团队的新旧负责人办理转交；只是姓名错字更正则走资料更正。

以上是待审阅的处理建议，保持在设备详情或现有交接表单内，不另增业务模块。

## 人员与团队名单

在选择接收对象时搜索已有名单，没有则就地新增。个人登记姓名和人员类型，所属单位与联系方式选填；团队登记名称和负责人。接收对象无需注册系统账号。

姓名相同的人用所属单位或备注区分，不能仅凭姓名自动合并。人员离开或团队不再使用时可停用名单项，历史保留；名下仍有设备则提示先核对去向，不自动视为归还。停用名单项与停用登录账号分别处理。

## 录错怎么办

| 情况 | 处理建议 |
| --- | --- |
| 未确认的草稿 | 经办人可修改或删除 |
| 名称、型号、位置、旧编号等资料录错 | 经办人更正并留痕；不能借改资料改变持有方，历史单据快照不变 |
| 确认错设备或接收方，尚无后续流转 | 管理员核对后作废并按原记录恢复状态，再开正确单据；保留原编号、原因和附件 |
| 已有后续转交或退回 | 不直接撤销早期记录；管理员先核对实际情况，按相关设备逆序处理错误记录，或以当前真实交接纠正去向，不能直接覆盖台账 |
| 签字件传错 | 未归档时重新选择或上传；已归档由管理员更正关联并保留原记录 |

实际已经交接的设备不能仅因纸面写错就自动变成“在库”。作废前必须核对事实；部分退回走退回单，不是作废原分发单。

## 提醒保持简单

建议页面仅列三类业务待办：待回传签字件、即将到期、已逾期。账号审核另显示在管理员设置入口。

- 默认提前 3 天提示临时领用到期；当天未归还不算逾期，次日起算。
- 到期邮件先发给办理该次分发或转交的经办人，账号停用时转给管理员，不要求设备使用人都提供邮箱。
- 邮件建议每日汇总一次，分别列到期和逾期设备；同一收件人同一天同类汇总不重复发送。
- 待回传签字件先只在系统显示，避免额外催办邮件；存量建账缺历史凭证不混入此列表。
- 延期后按新日期提醒；部分归还后只提醒仍未归还的设备。邮件失败不影响台账，可重试并显示发送情况。
- 上述天数和发送方式为建议默认值，不做复杂通知规则编辑器。日期采用项目配置的统一时区，具体时区实施前确定。

## 第一版收敛范围

保留设备台账、流转办理、单据记录三个主入口。人员与团队就地维护；账号审核和单位名称放管理设置。故障处理、延期、更正都作为现有记录上的操作。

不增加采购、财务折旧、复杂盘点、维修工单、消息中心或多级审批。首轮流程设计到此足以进入页面草图和单据样张评审，细节不要求用户逐条回答。

## 待实现时验证的场景

- 同一张分发单的三件设备归还一件后，其余两件持有关系和提醒仍正确。
- 个人转给团队后，负责人必填，原个人名下不再显示该设备。
- 登记故障不改变持有方，正常退回与故障退回产生不同可用状态。
- 管理员作废无后续流转的误单后，相关设备恢复到准确的原状态。
- 已有后续流转的单据不能直接撤销；归档附件更正可追溯。
- 同一设备再次领回沿用编号，实物换新则创建新编号。

本轮仅设计，未运行这些场景或任何应用测试。
