# 密码找回接入

状态：已获授权上线，迁移 003、入口私有配置及自有邮件函数已应用，找回发布开关已开启，页面与网关通过既有 CI/CD 发布。真实收码、改密和重新登录仍由本人在网站验收。

## 用户流程

登录页进入“忘记密码”，填写注册邮箱 → 收六位纯数字验证码 → 验证成功 → 两次输入新密码并确认共享账号影响 → 设置成功 → 重新登录。注册、审核、停用和角色状态不由密码找回更改。

页面仅在 `accountsEnabled` 与独立的 `recoveryEnabled` 都开启时使用此功能；旧配置缺少后者时默认关闭。请求采用统一提示，不公开邮箱是否存在。重发使用原 Auth 限流与有效期，不新增其他限额或修改共享参数。

找回使用独立内存客户端，验证码与恢复会话不进入 URL 或持久存储。验证失败不能进入改密步骤；验证后十五分钟未完成时要求重新验证，这个页面时限不改变共享服务的验证码有效期。返回登录、取消或离开页面时尽力退出该恢复会话，刷新后重新开始。

页面要求新密码为 12 至 128 个字符且两次一致；服务端仍采用现有共享密码策略。设置密码仅提交密码及官方 SDK 必要参数，不修改邮箱、metadata 或设备簿角色。

## 资格与邮件

[迁移 003](../database/migrations/202610180003_recovery.sql) 只新增 `gear.can_recover_password(uuid)`，返回该认证身份是否具有已验证邮箱和已启用的设备簿成员资格。固定空 `search_path` 的只读 `SECURITY DEFINER` 函数只授予 `service_role` 执行；该角色只新增 `gear` schema 使用权和这一个函数的执行权，没有新增表读取、写入或其他函数权限。匿名及普通登录者不能调用该资格查询。

邮件函数根据 `GEAR_AUTH_APP_URL` 与 Auth 传入的精确回调根入口识别设备簿的找回请求；不以共享用户的设备簿 metadata 判断请求来源。签名通过后，使用平台自带服务凭据调用固定的资格 RPC，检查通过才向 Gmail 提交六位验证码邮件。无资格时不发邮件并返回统一成功；查询失败则受控失败，不能绕过检查发送。

`SUPABASE_URL` 和 `SUPABASE_SERVICE_ROLE_KEY` 由平台默认提供，服务凭据仅在函数内用于固定资格查询，不复制到浏览器或网站 CI。新增的 `GEAR_AUTH_APP_URL` 是私有服务端配置；缺少新增配置不会阻止原注册和其他应用的通用邮件，正式开放前必须先检查找回所需配置完整。

收到正确验证码后，页面通过恢复身份的 `get_my_membership()` 再次检查当前资格，提交新密码前再次检查。跨服务操作无法与业务停用做同一数据库事务；设备簿每个业务请求仍按当前成员资格授权。共用身份也可由其他应用恢复其共享密码，设备簿停用不等于封禁整个 Auth 身份。

## 共享账号与会话

页面在提交前要求明确确认：该身份的密码与同一认证服务的其他应用共享，重置会影响其他应用后续登录。调用官方 `verifyOtp(type: recovery)` 和 `updateUser`，不使用管理 API 替用户指定密码。

上游当前实现会在密码更新时清理待用凭据及其他刷新会话，本流程再退出恢复会话及设备簿原会话，只清理设备簿自己的浏览器存储。已经签发的访问令牌可能仍有效到过期，不能承诺所有应用立即退出；上线验收仍须核对实际服务行为。连接中断时密码可能已经提交，页面提示可尝试新密码登录，不自动重复改密。

## 检查与部署记录

网关补齐了认证 API 版本响应头的跨域可见性，使官方 SDK 能将错误验证码映射到明确的中文提示。

本地检查覆盖十一项页面流程、十二项邮件用例及一次性 PostgreSQL 的账号检查。覆盖错误验证码、前导零、共享影响确认、密码不一致、验证后停用、恢复令牌不持久化、只清理自身存储、服务端只读资格与最小授权，以及其他应用找回模板保持原行为。浏览器和邮件接口使用虚构响应，数据库仅临时测试身份；没有修改真实管理员密码，没有发送真实找回邮件。

本次经明确授权执行的顺序：

1. 在既有项目应用迁移 003，确认匿名及登录用户无执行权。
2. 注入一项 `GEAR_AUTH_APP_URL` 私有配置，检查平台服务凭据可用。
3. 更新自有 `gear-auth-mail`，包括已获 Gmail 预览确认的中文编码修正和新的找回检查；保留其他函数、机密与 Auth 参数。
4. 通过仓库变量 `GEAR_RECOVERY_ENABLED=true` 和现有 CI/CD 发布页面。
5. 发布后由本人在网站发起找回并输入验证码，设置新密码后重新登录；此项尚待本人验收，令牌与密码只由本人在网站填写。

云端已核对资格函数的只读定义、最小授权、有效管理员与虚构身份的判断；真实邮件函数已通过无签名拒绝、有效签名无效载荷拒绝，以及虚构无资格身份不发信检查。后一检查使用平台自带凭据访问新 RPC，没有发送真实找回邮件或修改密码。
