# 邮件与通知设计

状态：已选用现有自有域名 Google 邮箱，通过 Gmail API 发信；完成独立的授权、令牌刷新及同域收件验证。应用尚未实现，下述通知行为为建议设计，需与业务规则一起实施和验收。

本文不保存真实邮箱、域名、云项目标识或凭据。示例发件人统一使用 `webmaster@example.com`，示例日常收件人使用 `operator@example.com`。

## 1. 通道和账号

- 适用于个人非商业用途的小型系统，约十名系统用户、不到一百件设备，以注册、日常通知及归还提醒为主。
- 使用独立的发件邮箱授权，发件人显示名称可设为“设备簿”。收件人可直接回复该邮箱，来信转发是否正常需另外验证。
- 发件邮箱仅授予 Gmail 的 `gmail.send` 权限；基础身份权限只用于核对授权账号，不读取邮件内容。
- 发信凭据与开发管理凭据分开。应用不携带 Workspace Admin 或云项目管理凭据。
- 系统仍采用账号密码登录。管理员为发件邮箱完成 Google 授权，不要求每名同事授权 Google，也不要求接收设备的所有人注册系统账号。
- Google 授权入口只在管理员接入或重新授权时使用；普通用户访问设备簿和操作通知链接不应依赖直连 Google 登录页面。

## 2. 第一版通知事件

| 事件 | 收件人 | 建议行为 |
| --- | --- | --- |
| 注册邮箱验证 | 申请人 | 按已确认账号流程发送有期限的验证链接；验证不等于管理员批准，重发需限流 |
| 注册待审核 | 系统管理员 | 先验证邮箱再通知有新申请；邮件不直接赋予权限，管理员登录系统办理 |
| 审核通过或拒绝 | 申请人 | 告知结果；通过后仍使用原来的账号密码登录，不发送原密码 |
| 忘记密码 | 符合重置条件的账号邮箱 | 一次性、有期限的重置流程；对外统一响应，不暴露邮箱是否注册 |
| 临时使用即将到期、到期或逾期 | 当前分配的系统经办人，账号不可用时为管理员 | 按现有建议每日汇总，同一人的多件设备合并发送 |
| 日常流转、签字件待回传 | 系统内记录和待办 | 第一版建议不逐次群发；邮件不替代单据、签字或归档 |
| 发信授权失效、持续失败或触发保护限额 | 管理员站内提示 | 保留异常与待发记录；不能只依赖已经失效的邮件通道报警 |

到期提示仍以[统一业务规则](business-rules.md)为准：建议提前三天、到期当天不算逾期、延期按新日期，退回、转交、遗失或报废后结束旧分配的提醒。签字件待回传默认只进入站内待办。

已确认邮箱验证为注册必经步骤，并在验证后进入管理员审核；具体流程见[账号与访问设计](account-design.md)。已经具备发信能力，不代表注册验证、审核或密码重置功能已经完成。

## 3. 邮件内容和链接

- 标题简短，正文包含通知原因、必要的单据编号或归还日期，以及进入系统的链接。
- 默认不附真实台账、完整人员清单或签字原件；需查看的内容留在系统内按权限访问。
- 普通业务链接要求登录并校验权限；密码重置等一次性链接需要过期、单次使用及防猜测保护，日志不得记录完整敏感链接。
- 邮件只是提醒。台账、正式单据、签字归档和账号审核结果以系统记录为准，邮件失败不回滚已完成的真实交接。
- 对其他项目复用时，发件人、回复地址和系统入口从私有配置读取，不写死真实地址。

## 4. 发送和失败处理

第一版用业务数据库中的待发记录即可，不为当前规模额外引入独立消息队列。需要通知的业务提交同时登记待发任务，后台发送，页面不等待外部邮件接口完成。

- 保留待发送、已提交邮件服务、失败、结果不明和已取消状态。接口接受请求不等于收件人收到，不显示未经验证的“已送达”。
- 用业务事件、收件人和提醒周期区分任务，防止重复登记；实际发送前重新检查当前业务状态，取消已不适用的旧提醒。
- 明确失败按原因处理；限流或临时服务错误按服务提示退避并限制重试次数，认证失效则等待管理员重新授权。
- 请求超时或响应中断可能已经发送，标记结果不明，不能直接当作未发送而无限重试；人工重发需要提示可能重复。
- 恢复备份后先核对待发记录，不自动重发历史通知。密码重置等已经过期的任务不得补发旧链接。
- 日志保留必要的业务关联、状态和错误类型，避免记录令牌、密钥、完整正文和敏感链接；真实运行日志不提交仓库。

## 5. 配额与运行边界

- 邮箱每日发信限额与 API 配额同时生效；同一邮箱其他客户端的发信也会占用邮箱额度。
- 当前正式帮助文档没有单列旧版免费账号的准确每日上限，不把普通付费 Workspace 的额度套用为本项目保证。
- 第一版采用保守限速、每日发送保护及注册/密码重置请求限流，防止公开注册接口消耗额度；具体阈值为实施建议，尚未确定。
- 通知优先使用简短正文与链接，减少大附件、重复提醒和批量群发。关注邮箱存储余量及授权失效。
- 不承诺永久不变的免费额度或投递时效；部署时复核官方政策与实际配额。

参考：[Gmail API 配额](https://developers.google.com/workspace/gmail/api/reference/quota)、[邮箱发信限制](https://knowledge.workspace.google.com/admin/gmail/gmail-sending-limits-in-google-workspace)、[错误与重试](https://developers.google.com/workspace/gmail/api/guides/handle-errors)、[令牌失效条件](https://developers.google.com/identity/protocols/oauth2#expiration)。

## 6. 验证范围和待办

已完成：独立的授权账号核对、最小发信权限检查、刷新令牌验证，以及一封同域测试邮件的发送和实际收件确认。证据中的真实地址、标识和凭据仅保存在私有环境，不进入公开仓库。

尚未完成：

- 外部邮箱实际投递、垃圾邮件情况及 SPF/DKIM/DMARC 结果检查。
- 发件邮箱来信自动转发到日常邮箱的验证。
- 正式服务端运行环境与 OAuth 客户端类型的匹配；当前桌面客户端仅用于独立验证，不视为部署方案完成。
- 认证系统的注册验证和密码重置邮件接入。Gmail API 是 HTTP 接口，不能直接作为 SMTP 服务器地址填写，须在最终选型时确认认证系统支持的接入方式。
- 实际提醒时间、业务时区、限速阈值、通知模板及大陆网络下邮件链接的全流程验收。

## 7. 私有配置与开源交付

客户端凭据、发信令牌继续保存在仓库外的私有凭据目录。当前不创建项目 `.env`；实施时根据运行环境选择本地环境配置或云端密钥存储，只提供使用虚构值的配置示例。

真实邮箱、域名、项目标识、回调地址等运行参数只能进入私有配置或私有运维记录。新增本地文件时维护 `.gitignore` 并检查实际暂存内容；不能依赖忽略规则清除已提交内容。
