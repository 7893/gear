# 设备簿前端

Vue 3、Vite、Vue Router 与 TypeScript，使用官方 Supabase JavaScript SDK 接入账号。页面采用简单表单和本地样式，不加载第三方字体或组件 CDN。

```sh
pnpm -C web install --frozen-lockfile
pnpm -C web run check
pnpm -C web run dev
```

`check` 包含 ESLint、Prettier、Vue/TypeScript 检查、Playwright 浏览器测试及正式构建。浏览器测试使用本地服务器和虚构 Auth/RPC 响应，不连接共享项目；首次运行需安装相应 Chromium。数据库事务另在隔离 PostgreSQL 中验证，这两类测试不代表真实发信和完整 Supabase Auth 集成已经通过。

## 配置与路由

构建产物不包含部署地址。运行时从 `/runtime-config.json` 读取 `apiUrl`、`databaseSchema`、`publishableKey`、`release`、`accountsEnabled`、`recoveryEnabled`、`inventoryEnabled`、`flowsEnabled`、`evidenceEnabled`；实际文件由已获授权的发布流程注入并忽略。`databaseSchema` 由同一个 `GEAR_DB_SCHEMA` 注入，与网关一致；缺失或格式错误时拒绝初始化，不回退到写死名称。只有公开 publishable key 可进入浏览器，管理密钥和发件令牌不进入本目录。

`accountsEnabled` 只有明确的 `true` 才开启账号服务。共享认证配置已获准接入，账号发布开关已开启；关闭时不创建 Auth 客户端，不发送登录、注册或会话刷新请求。GitHub 发布步骤通过仓库变量 `GEAR_ACCOUNTS_ENABLED` 控制此项：共享配置获准并检查通过后，开放入口供指定管理员本人注册、验证，再由部署者初始化权限并完成真实流程验收；不能以切换此变量替代共享配置审批或验收。

| 路由 | 内容 |
| --- | --- |
| `/#/` | 台账已开启且有权时进入台账，其他账号查看状态或提交使用申请 |
| `/#/account` | 账号状态、验证后提交使用申请 |
| `/#/login` | 邮箱密码登录 |
| `/#/register` | 注册；已有共享身份应直接登录 |
| `/#/verify` | 注册邮箱验证码及重发 |
| `/#/recover` | 找回密码，独立发布开关缺省关闭 |
| `/#/members` | 管理员审核、角色和停用处理 |
| `/#/diagnostics` | 保留的页面、网关和 Auth 只读连接检测 |

采用 hash 路由复用现有 Nginx 和 CloudFront，无需更改源站路由规则。设备簿注册使用六位纯数字验证码；注册后进入验证页并保留邮箱，邮箱不进入 URL，不需要跨浏览器的 PKCE 校验值。旧版 PKCE 回调的清理和交换仅保留兼容处理，不接收 URL fragment 中的隐式登录令牌。六位长度配置已获授权应用，页面按既有 CI/CD 发布；实际验收状态见[实施记录](../docs/account-implementation.md#六位验证码调整)。

## 权限边界

会话使用应用专属存储键，退出使用 `scope: local`。服务端按当前成员及邮箱验证状态授权；浏览器不能通过修改 metadata、表单角色或页面状态取得权限。刷新权限时先清除旧成员资料，失败或降级不继续显示旧管理列表；提交审核仍由数据库再次检查权限、版本和请求幂等键。

注册页面建议至少 12 字符；共享 Auth 当前服务端最短长度仍是原有 6 字符，尚未更改全项目密码策略。页面参数不能替代服务端限制。找回密码已加入独立开关，本次经授权开启并发布；普通已登录改密仍留待后续接入。

## 密码找回

密码找回的运行配置 `recoveryEnabled` 由仓库变量 `GEAR_RECOVERY_ENABLED` 控制，缺省关闭。本次已先完成迁移、私有配置及邮件函数检查，再经授权开启该变量并通过既有 CI/CD 发布。页面包含请求、六位验证、设置密码及重新登录，恢复会话只保存在独立内存客户端。服务端资格、额外私有配置和实际验收见[接入记录](../docs/recovery-implementation.md)。

## 审核通知状态

账号管理页已增加管理员可见的审核通知状态区，显示发送开关、各状态计数和最近二十条记录。界面区分“已提交邮件服务”和“送达”，只显示固定中文错误分类；读取通知失败不阻止审核，管理员失权后清空记录。云端迁移已获授权应用，该界面通过既有 CI/CD 发布；实际任务收件待本人验收，详见[审核通知接入](../docs/notification-implementation.md)。

## 存量建账与台账

台账、已有设备登记及设备详情已获授权通过既有 CI/CD 发布；`GEAR_INVENTORY_ENABLED` 控制运行配置的 `inventoryEnabled`，缺省关闭，本次在迁移和权限检查通过后开启。只有有权账号且开关开启时首页进入台账；账号状态保留在 `/#/account`。迁移 005、权限、未知日期、编号及上线边界见[本轮接入记录](../docs/inventory-implementation.md)。

设备台账默认每页二十条，可选十、二十、五十或一百条，提供首页、上一页、下一页及末页。查询或改变每页条数后回到第一页；筛选计数与全局统计不随翻页变化。当前规模使用现有完整查询结果在页面内分页，不增加数据库迁移。新增两个五十一条设备的分页场景，本轮合计四十五个浏览器场景通过。

## 流转与打印

已实现并获授权发布领入、分发、退回、草稿、单据查询和冻结快照打印；`GEAR_FLOWS_ENABLED` 控制 `flowsEnabled`，缺省关闭，本次上线已开启。办理入口 `/#/flows`，记录入口 `/#/documents`，详情和打印 `/#/documents/:id`。正式单据只读保存时的快照；草稿有显著标记。二维码本地生成 SVG，单据编号和页码使用打印页边距，桌面 Chromium 已检查五十条明细 PDF。接口、已确认编号、权限与上线范围见[流转实施记录](../docs/flows-implementation.md)。

## 签字件与人工归档

已本地实现正式单据详情中的原件上传、逐页预览、下载、二维码和 PDF 单号识别、手动关联更正及四项人工核对归档；前端代码随主分支发布，数据库和独立文件服务已按授权上线，本轮开启独立开关。`GEAR_EVIDENCE_ENABLED` 控制 `evidenceEnabled`，缺省关闭且依赖台账与流转开关。PDF 模块和 worker 按需加载并随网站提供，图片无二维码或 PDF 无内置文字时允许人工处理；不自动判断签字真实性。

附件新增十个场景，本轮合计四十五个浏览器场景通过。云端迁移 008、私有桶、隔离策略及独立文件函数已获授权部署，不把本地测试等同于真实签字和 Storage 验收。详见[签字件实施](../docs/evidence-implementation.md)。

## 公共界面与临时领用

操作按钮使用 `components/ActionGroup.vue`；公共样式集中在 `src/style.css`，按钮组统一十二像素间距并允许换行。账号页、账号管理、单据操作及分页已复用，现有链接操作区也采用相同间距规则。

台账与 `/#/due` 到期列表使用 `components/ListPagination.vue`，共享首页、上一页、下一页、末页、范围计数和页码重置；`src/pagination.ts` 统一条数选项与默认值。页面只提供当前授权数据和每页条数状态，通过插槽呈现业务列，不复制分页逻辑。角色、请求和业务表单仍使用已有业务模块。

临时领用详情提供逐设备延期，保留原期限、新期限及原因。迁移 009 已获授权应用，页面随本轮 CI/CD 发布；站内查询不代表归还邮件已经接入，见[临时使用实施](../docs/temporary-use-implementation.md)。

## 设备转交与负责人交接
