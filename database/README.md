# 数据库迁移

`migrations/202610170001_initial_schema.sql` 创建 `gear` 的十一张表、只读台账视图，以及 `gear_private` 的内部辅助函数。应用角色只有受 RLS 限制的读取权限，没有直接写表或取号权限。迁移不初始化管理员、人员或设备；唯一初始数据是通用设置，邮件开关关闭，提醒采用待启用的默认参数。

迁移 001 只建立基础结构。迁移 002 已新增申请、审核、角色和停用等账号 RPC，详见[账号接入记录](../docs/account-implementation.md)。审核通知的接口已随迁移 004 获授权应用云端；存量建账及台账查询接口已随迁移 005 获授权应用云端。迁移 006 已获授权应用云端，提供领入、分发、退回和草稿接口；转交与负责人交接已随迁移 010 获授权上线，单据作废及更正说明已随迁移 012 获授权接入，上传及人工归档的迁移 008 和独立文件服务已按授权上云，真实签字件的闭环验收待本人完成。内部设备编号已确认采用 `SB-000001`；领入、分发、退回单号前缀 LR、FF、TH 和共用业务日流水已确认，转交 ZJ 已随迁移 010 上线范围确认。

## 隔离验证

需要 PostgreSQL 16 或更新版本的服务端二进制和 `psql`。本地按目标环境使用 17，CI 复用 Ubuntu runner 已有的 16 检查兼容性。可用 `PG_BINDIR` 指定其 `bin` 目录，然后运行：

```sh
python3 database/tests/check_schema.py
python3 database/tests/check_accounts.py
python3 database/tests/check_notifications.py
python3 database/tests/check_inventory.py
python3 database/tests/check_demo_inventory.py
python3 database/tests/check_flows.py
python3 database/tests/check_temporary_use.py
python3 database/tests/check_transfers.py
python3 database/tests/check_asset_condition.py
python3 database/tests/check_document_review.py
python3 database/tests/check_evidence.py
python3 database/tests/check_schema_year.py
```

脚本自动创建临时数据库集群，只监听权限受限的临时 Unix socket，不接受数据库 URL。清除继承的 `PG*` 连接参数；测试结束停止并删除集群。测试 Auth 表和身份函数是最小替身，所有人员、设备和邮箱均为虚构，不能替代真实 Supabase Auth 的集成验收。

验证涵盖：迁移重跑安全失败、十一表 RLS、无关结构保留、同设备并发唯一分配、团队更换负责人保留分配身份、未知日期、重复旧编号、正式快照冻结、草稿删除、附件就绪与人工归档、未审核身份隔离、停用或失去邮箱验证立即失权、账号删除保留历史、日流水并发及东八区跨日、失败事务回滚。领入、分发与退回 RPC 的幂等及原子交接已有本地隔离覆盖；正式单据作废及更正已有隔离检查并随迁移 012 获授权接入，完整业务验收仍待本人完成；附件上传及更正已按迁移 008 获授权上云，真实签字件待验收。

[bootstrap_admin.sql](bootstrap_admin.sql) 由部署者使用私有环境中的 `GEAR_ADMIN_EMAIL`、`GEAR_ADMIN_DISPLAY_NAME`，在指定身份验证邮箱后手动执行；没有真实邮箱、默认密码或公开提权入口。指定首个已验证账号已完成初始化，真实身份仅保存在私有环境，管理员入口已由本人确认可见。

## 应用范围

原始迁移 001–006 保留当时的 namespace；迁移 007 将其改为创建年份后缀，后续迁移使用新名称。迁移按文件名顺序由数据库拥有者手动执行，包含完整事务及锁定、执行超时；001 遇到已有目标 schema 即失败，002 遇到已有同名函数即失败，均不能覆盖或清空已有结构。不删除业务数据或 schema，不安装共享 Auth 注册触发器。迁移 008 为扩展附件预留与取消事件，明确替换事件类型检查约束且保留全部旧值；Storage 隔离策略在单独脚本中，未随迁移自动执行。外键引用共享 `auth.users`，相应系统维护的参照完整性触发器由 PostgreSQL 创建，不安装自定义 Auth 触发器。

云端执行前核对目标项目和 schema，并保存现有结构与配置的脱敏指纹；执行后读取新结构元数据确认。连接凭据和云端原始检查结果只保留在私密目录。现有网站 CD 不执行 SQL；推送迁移文件不会自动修改数据库。

初始化失败会整体回滚；初始化成功后再次运行也会整体失败。后续变更新增迁移，禁止通过删除后重建规避差异。已有业务数据后的回退须另行设计和授权，不能自动删除台账或签字凭证。

## Schema 命名与配置

迁移 `202610190007_schema_year.sql` 将 `gear` 改为 `gear_2026`、`gear_private` 改为 `gear_private_2026`。保留原有对象身份、表数据、编号序列、所有者及授权；同步修正字符串函数体和本应用唯一调度的命令。年份固定为创建年份，不按年更换。应用统一读取 `GEAR_DB_SCHEMA`，不在各调用点写死名称。

已有服务滚动发布时，可在迁移事务内设置 `gear.rename_compatibility=on`，临时创建最小权限的旧名 RPC 转接；新安装缺省不创建。确认所有运行环境与 Data API 切换后，单独运行 [retire_schema_aliases.sql](retire_schema_aliases.sql)清理带精确标记的转接对象，遇到未知对象或依赖即回滚，不使用 CASCADE。隔离检查覆盖数据、序列、对象身份与权限保持、其他应用和调度不变，以及兼容和清理。

当前数据库改名的执行状态见[统一命名记录](../docs/schema-naming.md)；迁移 008、Storage 与文件函数已在后续按单独授权部署。网站 CD 不执行这些脚本。
