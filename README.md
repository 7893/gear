# 设备簿 · gear

面向个人经办或百人左右单位内部使用的轻量设备管理系统。

管理设备从领到手、分发使用、转交，到正常或故障退回的全过程；通过设备台账查询当前去向，并通过编号单据和签字附件保留交接凭证。

## 当前阶段

已进入第一阶段账号实现：注册验证、登录、申请状态和管理员审核页面及账号事务 RPC 已加入项目并通过隔离验证，数据库账号迁移已应用。共享 Auth 回调、API 暴露和 Gmail 发信 Hook 尚待单独批准，线上账号入口默认关闭，真实注册和首次管理员尚未验收。既有 CloudFront、独立 Nginx、Cloudflare 网关及亚太 Supabase 的真实浏览器连接已跑通，原检测页继续保留。设备台账、流转、附件桶及大陆完整业务闭环仍待实现和实测。优先免费、复用资源和减少维护，不再制作样稿。

使用 TypeScript 编写前端及所需的 Supabase Edge Functions，数据库结构、约束与事务使用 SQL。本轮沿用此前建议，在 [web](web/README.md) 初始化 Vue 3 + Vite + Vue Router；账号页面采用简单表单和本地样式，暂不引入组件库，依赖版本已锁定。详见[技术记录](docs/technical-proposal.md#开发语言与前端方案)。

前端客户端 HTTPS 证书已由 Google Trust Services 签发并导入 AWS ACM，供 CloudFront 使用；独立回源站点同样使用 Google 证书，已设置专用自动续期任务。后端域名使用 Cloudflare 自动管理的证书，详见[证书方案](docs/technical-proposal.md#客户端-https-证书与续期)。

公开 GitHub 仓库已建立，本地通过 `origin` 关联；部署地址等参数保存在仓库 Actions Secrets，真实 `.env` 和凭据不提交。仓库工作流检查文档、配置模板、凭据泄漏、提交规则、网关、静态测试页和隔离数据库结构；主分支检查通过后自动发布网关与网站、刷新 CDN，并以真实浏览器验证，首次完整自动发布已通过。部署凭据与权限已按授权配置，开源许可证待选择。

## 协作约定

- 优先简单实用，围绕经办人的日常操作设计。
- 区分已确认需求、设计建议和待确认事项，不把建议视为已定案。
- 当前实现账号这一阶段；设备台账和流转按后续阶段推进，不把局部检查通过视为完整业务验收。
- Git 提交必须签名，提交信息使用不超过 7 个单词的英文。
- 公开文档、源码、配置模板和示例只使用虚构信息；邮箱和域名示例使用 `example.com` 等保留示例域名，不记录真实邮箱、域名、账号、云资源标识、源站 IP、CDN 分配地址或其他部署访问地址。
- 部署地址通过环境变量注入；本地真实值放在已忽略的 `.env`，权限设为仅当前用户读写。远程仓库已关联，已配置的部署参数使用 Actions Secrets 管理，不写入工作流、提交信息、日志或截图。环境变量名见 [.env.example](.env.example)，未知值留空，不根据示例猜测真实配置。前端运行时使用的公开地址仍可被浏览器查看，不能作为身份凭据。
- 真实环境记录优先保存在仓库外；确需在工作目录留存的私有说明放入已忽略的 `.private/` 或 `docs/private/`，真实数据、签字附件、备份和凭据均不提交。
- 提交前检查暂存内容；新增本地私有文件时同步维护 `.gitignore`。忽略规则不能保护已跟踪文件，也不能移除历史记录中的信息，发现此类情况需单独处理。
